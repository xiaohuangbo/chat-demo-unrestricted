## 10. Known limitations

1. **There is no "off" for `safety_check`**: omitting it equals `low`, which is the lowest level the API offers; the server still runs its default check.
2. **Server-side alignment remains**: a model-initiated refusal (`stop_reason: 'refusal'`) cannot be cancelled by the client. Anti-retraction only keeps what was already streamed; it cannot make the model continue refused content.
3. **Historical chain-of-thought is never sent back**: by protocol, the server drops history thinking and the client does not resend it. Editing the thinking therefore affects the UI and the continuation prefix, while only the body applies to ordinary later turns.
4. **Sampling parameters are constrained in thinking mode**: the server fixes temperature at 1, and Top P below 0.95 is treated as 0.95.
5. **`max_tokens` includes thinking tokens**: setting it too low can truncate the thinking as well.
6. **Edits only affect the local context**: they do not re-request the model and do not change what the server already produced. Exports store the edited content; the original snapshot is not exported.
7. **Attachment limits, key validation, and speech endpoints** still follow the original logic and are independent of the switches described here.
8. **The lab is not a purely static capability**: it needs the local Python + MCP backend (`mcp-server/`), and a single job can issue a large number of model calls. Start with `limit=1` and small iteration counts.
9. **A custom prompt overrides the assembly**: once filled, unrestricted mode no longer swaps `system` (it still skips the safety check and allows continuing refused replies). Clear the box to go back to the default pipeline.
10. **Long-chat compression is lossy**: summaries drop detail, and auto-compression triggers at 80% of the window (about 800k tokens on a 1M window), so manual compression is the practical option. Per-chat system prompts and compression summaries live only in local sessions and are not included in history exports.
11. **Branch to new chat copies the current visible branch**: other answer versions and drafts are not copied; attachments reuse the original file ids; the new chat starts its statistics at zero and inherited usage is not counted.
12. **Restore default settings keeps the API key**: it only resets preferences and switches, never chats, attachments or statistics.
13. **Auto jailbreak and variant races cost extra**: every retry and every variant is a real request; variant races are bounded by the budget cap.
14. **Cloud model lists depend on the API and network**: a failed fetch falls back to the two built-ins; models without a price entry are estimated at Flash rates with a 128k window, and actual capabilities come from the server.
15. **Switching models does not rewrite old replies**: old replies keep their model and cost; continuations keep that reply's model, and only new replies use the current choice.
16. **Auto-extraction costs an extra call**: one Flash request per turn; long-term memory and the memory graph stay on this device and are not exported.
17. **The memory graph uses local hashed vectors**, not semantic embeddings: retrieval is approximate but needs no external service; changing the dimension recomputes vectors.
18. **Daily usage only counts chat replies**: MCP lab, races and title generation are not included; costs are estimated from current peak/off-peak rates and may differ slightly from the bill.
19. **Custom and special locations only affect `latest_reminder`**: they do not change weather, web search or server-side regional behaviour.
20. **Disguised thinking only covers the previous round**: it is sent as ordinary text, so the server no longer treats it as thinking; token usage rises slightly.
21. **The relation graph draws at most 80 nodes**: extra nodes are still searched, just not drawn; importing in Replace mode overwrites current long-term memories and graph data, so export a backup first.
22. **The stream-output switch only controls rendering**: when off, replies are still received over SSE and accumulated, just not shown mid-flight; accumulated content is written back when the page is hidden or closed to avoid loss.
23. **Search poisoning is not a server-side proxy**: server search runs on the server and the client only sees what the model already consumed; with takeover off it can rewrite display only, not retract this turn’s results.
24. **Takeover depends on custom results**: with no custom results it does not disable server search (unless a blacklist / whitelist is present); with takeover on the model only sees the configured results and real search does not run.
25. **Custom time / knowledge cutoff are hints**: they only affect `latest_reminder` and the injected context, not the UI, billing, weather or server region detection, and the model may not fully obey the cutoff.
26. **Attachment poisoning only affects new / re-uploaded attachments**: server files for messages already sent are not rewritten; attachments in the input box with a local original are re-uploaded on the next send with the current config, while imported files without an original stay as-is and sent history is never rewritten.
27. **Client-side rewriting is best-effort**: image text overlay needs Canvas, while PDF trailers and image metadata are experimental and not guaranteed to be read; prefer the companion text attachment for PDF / Office.
28. **Companion text attachments use an attachment slot**: none are generated when the limit is full; restoring defaults only clears the local config and generated companions in drafts, not server or historical attachments.
29. **Image text overlay re-encodes the image**: GIF / animations become static and GIF / BMP may become PNG; the file trailer skips ZIP-based Office files.
30. **The Python backend does not run inside the APK**: EasyJailbreak / torch cannot be packed into a normal WebView APK; the bundled backend sources are for reference and the lab must connect to an MCP service on a PC or server.
31. **The APK is a WebView shell**: browser capabilities such as file downloads depend on the system WebView; the local server occupies port 18765 and shows a startup error if the port is taken.
32. **Custom chain of thought is prompt guidance, not a real reasoning channel**: with deep thinking off, the card above the reply shows the steps you wrote, not live model reasoning; the model may not follow every step; each request increases input tokens and the text is capped at 4000 characters.
33. **With deep thinking on the custom chain is experimental**: server-side thinking takes priority and may ignore or rewrite the steps, so results are not guaranteed to match direct injection; the injected card is not repeated and server-side thinking is shown instead.
34. **Custom chain of thought only applies to chat requests**: race, variant race, long-chat compression and memory extraction use their own system prompts and ignore it; the first chat request that also generates a title still receives it.
35. **The “Injected chain of thought” card is local display data**: history export does not include it, so an imported archive does not show the card; continue reuses the reply’s snapshot and regenerate reads the current settings.
36. **Browser tools inherit browser limits**: page fetching is bound by the target site's CORS; notifications, location and clipboard need permissions (notifications are usually unavailable inside the APK WebView and are marked disabled); “open link” can be blocked by popup rules.
37. **Tool round trips are billed per round**: up to four round trips per reply, each a real request, so tokens and cost accumulate; with the master switch off the model cannot see any tool.
38. **NanoVM Slim is a browser-side simulation**: not a real Linux kernel — no process isolation, no multi-user permissions, no signals or job control; `&` does not survive, and `kill` / `nice` / device files do not exist. Its files and quotas are local, so clearing site data wipes them.
39. **The busybox commands are subset implementations**: `awk` has no `printf`, arrays, loops or user functions; `sed` has no `{}` blocks or `r/w/l`; `sort -h/-M/-V`, `grep -A/-B/-C` and `find -mtime/-size/-perm` are missing. Unsupported usage **fails loudly** instead of silently returning the wrong result.
40. **`npm` and `pip` are not available**: Node.js is a browser-compatible runtime (a `fs` / `path` subset inside a Web Worker) and Python is Pyodide (WASM CPython — pure-Python packages work, C extensions need Pyodide's built-in support). Install real dependencies on the host.
41. **`curl` / `wget` are subject to CORS**: only targets that allow cross-origin requests work, and failures say whether it was the network, CORS or an HTTP status — never a fake success.
42. **Scripts in the VM become commands**: a script with the executable bit runs by path or through `$PATH`, with shebangs for `sh` / `bash` / `python3` / `node`; without a shebang it fails like Linux with `Exec format error`. One consequence: `exit 3 | cat` ends the whole script (pipeline stages are not real processes) instead of only the pipeline subshell.
43. **The first toolchain install needs the network**: Python is about 12 MB (Pyodide) and is cached locally afterwards; Node.js and Git are built in and need no download. Git is local-only — no `clone` / `push` / `pull`.
44. **Workspace capacity**: in OPFS mode the limits derive from `navigator.storage.estimate()` (up to 80% of the quota, capped at 64 GB total / 256 MB per file) and grow with the quota; localStorage cannot be expanded (typically 5–10 MB, and base64 adds roughly a third), so a full write tells you to switch to OPFS. Export a ZIP before clearing or replacing.
45. **The workspace is not part of history exports**: history archives keep conversations and images; workspace files and tool cards are not included, and clearing site data loses them.
46. **OPFS and persistent storage vary by browser**: older WebViews and private modes may not support OPFS, leaving localStorage as the only option; `navigator.storage.persist()` can also be refused, in which case the browser may still evict data when space is low — export a backup for anything important.
47. **Switching storage overwrites the target backend**: switching to OPFS replaces the OPFS directory with the current files, and switching back overwrites the localStorage copy; export first if in doubt.
48. **The context breakdown is an estimate**: character weights (1 token per CJK character, 4 characters per token otherwise) differ from server billing; the KPI numbers reported by the server stay authoritative.
49. **Chat modes only affect client tools**: server tools (read URL / web search) are sent in all four modes, including Chat only; the mode is a global choice (`chat-demo:chat-mode`) and is not stored per session.
50. **PTC / Creator run the tool calls of one round in parallel**: several tools that need confirmation queue up one dialog at a time; in Creator mode NanoVM tools skip confirmation, so a wrong path, a careless `rm` or a bad install is on the user — try it in a throwaway chat first.
51. **All tool calls of one round share that round's usage**: parallel NanoVM commands are billed and counted in context per round trip, not separately.
52. **The VM has no real ICMP or DNS**: `ping` probes over HTTPS (timing a `HEAD` / `GET`), so a host that answers no HTTP is not necessarily down, and there is no `nslookup` / `dig`.
53. **Networking cannot bypass the browser security model**: the APK's built-in proxy only serves this app (token-checked, bound to 127.0.0.1), while plain browsers stay limited by CORS. A custom proxy sends the target URL to a third party — decide for yourself whether you trust it.
54. **The new toolchains need the network too**: Lua (wasmoon, ~0.4 MB), SQLite (sql.js, ~1.3 MB) and esbuild (esbuild-wasm, ~12 MB) are downloaded from jsDelivr on first install and cached afterwards; `make` is built in, so it installs offline.
55. **Every runtime here is a subset**: esbuild can only bundle files inside the VM (no npm resolution, no plugin ecosystem), SQLite is sql.js (no FTS / extension modules), Lua has no `os.execute` / `io.popen` host access, `make` has no parallel builds, `$(call)` / `$(eval)` or target-specific variables, and `jq` covers the common filters only; `timeout` returns 124 but cannot actually kill the child command.
56. **The virtual network is CGI, not real sockets**: every request to a `vm serve` service re-runs the command (cold start); there are no daemons, keep-alive, concurrency or long-lived connections, request and response bodies are buffered, nothing outside `curl` can reach those ports, and a service that requests itself more than three levels deep is rejected.
57. **Go / Rust / C / C++ have no in-browser compiler**: none of the official toolchains ship a `go` / `rustc` / `gcc` that runs inside browser WebAssembly, so NanoVM does not fake one. Backends can be written in Node (`http` / `ws`) or Python (Flask or the `nanovm` micro framework) on the virtual network; if you really need a Go / Rust / C binary, build it on the host and wire the artifact or the API in.
58. **WebVM needs cross-origin isolation**: CheerpX relies on `SharedArrayBuffer`, so the page must send COOP/COEP. On static hosting the first enable registers `coi-sw.js` and reloads once; `file://`, plain-HTTP LAN origins (other than localhost) and browsers with service workers disabled cannot enable it. Once on, same-origin third-party iframes and cross-origin images may be affected by COEP (`credentialless` reduces this); if embedded content goes blank, disable WebVM. **Android WebView does not support cross-origin isolation, so WebVM cannot run inside the APK**; use Chrome on the phone or a desktop browser for the online version.
59. **WebVM streams about 2 GB on first boot**: the CheerpX runtime comes from `cxrtnc.leaningtech.com` and the root filesystem from `disks.webvm.io`; a first boot usually takes 30–90 seconds and longer on slow networks. Later launches use the IndexedDB overlay, but clearing site data, switching images or resetting downloads blocks again.
60. **WebVM is a 32-bit x86 Debian 10**: packages are frozen at buster, there is no `npm` (only `node`), no `apt` network and no Tailscale. For newer toolchains, native extensions or package management, use NanoVM, the host, or your own custom image.
61. **One WebVM has one console**: unlike NanoVM's tabs. NanoVM and WebVM can run simultaneously, but WebVM has a single bash; model commands reuse that shell and run serially, so if the user is running a foreground command the model command queues behind it or times out, and Ctrl+C may interrupt both.
62. **WebVM import/export is bounded**: at most 50 files / 20 MB per batch; export is a tar.gz of `/home/user` (captured as base64, 32 MB cap), not a whole-disk image. Reset wipes the IndexedDB overlay and every file created or changed inside the VM.
63. **The WebVM agent tool allows up to five minutes on its first call**: the first boot waits for image blocks; later commands usually finish in seconds. A timeout only guarantees that the tool returns — a command that already started may still finish in the VM, and its output goes back to the terminal.
64. **CheerpX is proprietary software**: Leaning Technologies allows free use for personal and open-source projects; commercial use needs a commercial licence. The runtime and default image come from their CDN, and each deployment must decide whether that dependency is acceptable.
65. **The two VMs do not share a file system**: NanoVM's zip image and WebVM's tar.gz are not interchangeable and must be unpacked and imported manually; `/home/user` is a separate directory in each, so the model must know which VM it is operating on.

66. **Keyword refusal is a local substring match**: it only checks user text, not attachments, image text or model output, and performs no semantic moderation; Chinese is unaffected by case, while English is lower-cased when case sensitivity is off. A match skips the API, search and tools, but it cannot stop a user from rephrasing.

67. **WebVM root is password-based inside the image**: `sudo` is implemented on top of the image's setuid `su`, with the fixed root password `password`; it is not the real sudo package and only changes permissions inside the VM, never on the host. `sudo` in non-interactive scripts or agent commands waits for a password and may time out; use it in the terminal or click the Root button.

---

68. **Local models need WebGPU**: in-browser models run on WebGPU; without `navigator.gpu` or a GPU adapter you have to fall back to the MLC-LLM API, and Android WebView has no WebGPU either, so the APK is in the same boat. Software rendering (SwiftShader) usually lacks `shader-f16`, so q4f16 models fail to load there; pick q4f32 or use a real GPU.

69. **Weights come from the public internet**: WebLLM model libraries and weights live on GitHub Raw and Hugging Face, so a restricted network breaks downloads; already downloaded models keep working and can move between devices as `.mlcmodel` bundles.

70. **Browser storage is quota-limited**: a 1B model needs roughly 0.7–1 GB and an 8B model 4–5 GB; running out of quota aborts the download, so keep only one or two models, or switch to IndexedDB / delete old models.

71. **Local models are text-only**: attachments, images, server-side web search and client tools are not sent; switch back to a cloud model when you need them.

72. **Bundle size equals cache size**: `.mlcmodel` does not compress (weights are already compressed), so exporting a 4 GB model writes a 4 GB file; browsers without File System Access stage it in memory, where very large models may fail.

73. **The MLC-LLM API needs your own server**: this project is only the client; start `mlc_llm serve` yourself. The endpoint and model list are unauthenticated, and cross-origin access must be allowed by the server.

74. **Local web search needs an API key**: search is a pre-generation server-side pre-pass (DeepSeek Flash plus server search). Without a key the turn simply skips search with a notice and the local chat continues.

75. **Local model attachments are text-only**: txt / md / csv / json / code files are injected as plain text, capped at 8K per file and 24K characters in total; images and binary files are skipped with a notice — switch back to a cloud model for images.

76. **Characters and My profile stay on this device**: `chat-demo:roles` and `chat-demo:profile-*` are not part of history exports, so a new device starts from scratch; a role prompt enters the system prompt and can noticeably change the answering style.

77. **Local models allow Chat mode only**: Agent / PTC / Creator are disabled, and search is a pre-pass rather than a model tool call; switch to a cloud model when you need tools.

78. **Prompt and CoT presets stay on this device**: up to 30 each, stored as `chat-demo:system-prompt-presets` / `chat-demo:cot-presets` and not included in history exports; deleting the active preset clears the current prompt text.

79. **NanoVM single-file import is capped**: a hard 256 MB per-file limit and a 2048 MB maximum disk; the disk grows before writing, and very large files make OPFS persist the whole filesystem as base64, which can take seconds to tens of seconds, so keep the page open.
80. **PyBot startup is not instant**: each question syncs ~39 MB of source into Pyodide and imports 528 modules, measured at about 8 s; it needs the Python toolchain (~12 MB), and the offline snapshot is pinned to commit 24cbc04 — update it by rebuilding `public/pybot.zip`; while an interactive session is active, terminal input is treated as chat, so run `/exit` before shell commands.
81. **V4 Pro lacks web and image capabilities**: the server explicitly rejects `deepseek_web_search` / `deepseek_read_url` / `title` / `latest_reminder`. This app drops those fields for V4 Pro, folds the date reminder and compression summary into system, names new sessions from the first question and disables the Search toggle; image blocks do not error but the model cannot see them. Switch to DeepSeek Flash for web access, cloud titles or images.

82. **Unkernel needs JSPI; the page is about 127 MB**: the kernel uses `WebAssembly.Suspending` / `promising` (Chrome / Edge 137+, Firefox 153+, Safari 27+); an old Android WebView shows a boot error, so use the online build on a current browser. The page (desktop, 80+ app definitions, the kernel and the Alpine / Debian images) is about 127 MB — Alpine 3.9 MiB, Debian 74.2 MiB and DSH go 24 MiB — so the APK grows to about 118 MB; Debian streams its image on first boot. Multi-CPU needs cross-origin isolation, which the desktop static build enables once and reloads into Unkernel; Android WebView does not support it, so one CPU only. Networking uses public Wisp proxies by default (anura.pro / mercurywork.shop; their operators see the host names, ports and plain-HTTP content the guest connects to, while TLS stays end to end); if they are unavailable, set a custom `wss://` endpoint in Settings → Unkernel Linux. The data disk defaults to 8 GiB and can grow to 16 / 32 GiB or be reset, which erases `/data` and the saved snapshots. Memory is not set here: the VM page’s own Settings → Machine owns it, the host passes no `mem`, and page-side changes survive restarts. The other boot parameters (distro, data disk, CPUs, devices, Worker, Wisp) still follow the host panel when it restarts the VM.
83. **`tool_choice` conflicts with several fields**: the Anthropic-compatible endpoint accepts no `tool_choice` in thinking mode, and `safety_check`, server tools (`deepseek_read_url` / `deepseek_web_search`) or `title` alongside it are rejected as thinking mode too. With forced tool choice, the prompt-injection tool therefore disables thinking, skips the title and drops the safety check and web tools for that round — so that round has no web search and no server-generated title (the first turn falls back to the first 24 characters).
84. **Injection-tool history restoration yields to reminders**: when a historical reminder snapshot changes (day change, different location), restoring the previous answer as `tool_use` would put the reminder between `tool_use` and `tool_result`, which the server rejects; those rounds fall back to plain text, trading shape consistency for protocol correctness.
85. **The new Unkernel page’s apps need the network on first run**: the 80+ apps download files and install packages from distro mirrors on first launch (Steam, Zed and friends range from tens to hundreds of MB) and stop at the installer when the network is unavailable; DSH go ships with the page and needs no download.
86. **Memory node filtering only affects the list**: the search box and tag buttons filter the settings list; they change neither the retrieval parameters, the number of injected nodes, nor the graph data, and the filter is not persisted (it clears when the settings group changes).
87. **apt and plain HTTP go through Wisp, not the unkernel mirror**: the upstream page hands plain HTTP to `deb.debian.org`, `apt.ladybird.org` and `mirror.unkernel.dev` to its own CORS mirror at `https://mirror.unkernel.dev`, answered by the page’s `fetch()`. That mirror keeps an Origin allowlist — `https://unkernel.dev`, `http://localhost:*` and a few others — so this app, served from `127.0.0.1:3080`, a LAN address or the APK’s `http://127.0.0.1:18765`, only ever gets `403 Origin not allowed` (which is why Debian’s apt reported 403). The iframe therefore always carries `routes=0`: the guest’s plain HTTP takes the public Wisp proxies too. The cost is that apt indexes and `.deb` files cross a third-party proxy (its operator sees plain-HTTP content; TLS stays end to end) and are limited by its bandwidth; apps that rely on that mirror (Ubuntu’s tarball, for instance) fall back to their upstream and may stop at the installer for files only the mirror carries. For speed or privacy, set your own Wisp endpoint in Settings → Unkernel Linux, or point the guest’s apt sources at `https://deb.debian.org` (port 443 already goes through Wisp and never touches the mirror).
