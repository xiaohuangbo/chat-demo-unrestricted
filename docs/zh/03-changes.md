### 3.2 解除限制模式（越狱模式）

**位置**：设置 → 提示词。

**原理**：系统提示词从「一句身份说明」变成一条组装流水线：

```text
Persona（官方身份分块）
      │
      ▼  [解除限制模式]
      ├─ 开启：追加「破限规则分块」，并强制跳过安全审核、允许继续生成被拒回复
      └─ 关闭：只下发 Persona，原样放行官方默认提示词
      │
      ▼
请求体 system 字段
```

- 破限规则来自仓库根目录的 [`deepseekv4.1 and v4.1-1017.md`](<../.././deepseekv4.1 and v4.1-1017.md>)，构建时由 rspack 以 `asset/source` **原样内联**进产物，运行期不依赖该文件；
- 组装时自动做两处归一：切掉文末残留的示例回答骨架、把 `{{PAYLOAD}}` 替换成「the request in the latest user message」；
- 设置页可以展开预览**本次请求实际会下发的 system 全文**；
- 开启后强制两项：`safety_check` 字段不发送、被拒回复允许继续生成（对应下面 3.5 / 3.6 的两个开关会显示为已开启并置灰）；
- **自定义系统提示词**（同分组的输入框）：留空时仍走上面的流水线；填写后把内容原样作为 `system` 下发，自动组装结果不再生效——此时越狱模式仍会跳过安全审核、放开被拒回复续写，但不会替换提示词。输入框下方「填入默认」把当前组装结果填进去作为起点，「恢复默认」清空覆盖。

### 3.3 模型参数

**位置**：设置 → 模型。

| 参数           | 控件            | 范围 / 步长       | 默认 | 下发方式                      |
| -------------- | --------------- | ----------------- | ---- | ----------------------------- |
| 温度           | 滑块 + 数字输入 | 0–2，步长 0.05    | 1    | `temperature`                 |
| Top P          | 滑块 + 数字输入 | 0.01–1，步长 0.01 | 1    | `top_p`                       |
| 最大输出 Token | 数字输入        | ≥1，可留空        | 留空 | 留空时**不发送** `max_tokens` |

- 滑块与数字框双向同步：输入框失焦或回车提交，超范围自动夹到区间、按步长取整；
- 全部持久化到 localStorage，下次打开自动恢复；
- 每次请求都会带上（最大输出 Token 除外，留空即不下发）。

### 3.4 防撤回

**位置**：设置 → 模型。

原版在 `stop_reason: 'refusal'` 时会把已经流式输出的正文和思维链删掉；打开防撤回后改为**保留**：

| 行为                  | 防撤回关闭（原版行为）           | 防撤回开启                                                               |
| --------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| 已下发的正文 / 思维链 | 全部删除                         | 保留并正常展示                                                           |
| 界面提示              | 显示固定模板答复                 | 内容下方一行提示「本轮回答被安全审核拦截，防撤回已保留模型已输出的内容」 |
| 后续上下文            | 该轮不参与                       | 正文保留后**照常进入上下文**                                             |
| 编辑按钮              | 不可用                           | 可用（内容保留后按正常回复处理）                                         |
| 导出历史              | 标记为 `CONTENT_FILTER` 并附模板 | 按正常结束导出，重新导入不会被再次清空                                   |

防撤回与越狱模式相互独立，越狱模式不会自动打开它。

### 3.5 跳过安全审核

**位置**：设置 → 模型。

- 关闭（默认）：请求照旧携带 `safety_check: { level: 'high' }`；
- 开启：请求体**不再包含 `safety_check` 字段**（`undefined` 在 `JSON.stringify` 时被丢弃）；
- 越狱模式开启时自动跳过并置灰。

按官方文档，不传 `safety_check` 与传 `low` 完全等价，这是 API 允许的最低档，没有更低。

### 3.6 拒绝后继续生成

**位置**：设置 → 模型。

- 关闭（默认）：`canContinueReply()` 对 `stopReason === 'refusal'` 直接返回 `false`，「继续生成」按钮不出现（原版行为）；
- 开启：被拒回复按「正常结束」参与续写判断，最后一条被拒回复下会出现「继续生成」；
- 越狱模式开启时自动放开并置灰。

其余续写限制不变：模板提示、服务端工具块、非前缀消息仍然不能续写。

### 3.7 回复改写

**位置**：每条 AI 回复下方的操作条，复制 / 朗读 / **编辑（铅笔）** / 重新生成。

- 点铅笔就地展开编辑器：上方**思维链**（该回复有思考时才出现），下方**正文**；`Ctrl/Cmd + Enter` 保存，`Esc` 取消；
- 保存直接把内容**写回消息的内容块**，不新建分支、不重新请求；之后每一轮组装上下文时读到的都是改写后的版本；
- 写回规则：思维链写入第一个思考块（没有则在最前面新建一个）、其余思考块清空；正文只作用于末尾那段「回答」的第一个文本块、其余文本块清空，正文变化会丢弃失效的引用标记；工具块、模板提示、思考签名一律不动；
- 首次改写会保存一份原始块快照，编辑器里的「还原原文」可一键恢复；
- 续写会让快照与追加后的内容对不上，因此续写后不再提供还原；
- 被安全拒绝且内容已被丢弃的回复不可编辑（没有可改的模型正文）；开了防撤回、内容仍在的可以。

### 3.9 越狱实验台（可选，需本地 MCP 后端）

侧边栏底部新增「实验台」：通过 MCP 连接本地 `mcp-server/`，把 EasyJailbreak 的攻击器搬进浏览器界面。

- 后端：`mcp-server/`（Python，MCP Streamable HTTP，默认 `http://127.0.0.1:8765/mcp`），启动 `./mcp-server/run.sh`；
- 前端：`src/services/lab/`（MCP 客户端）+ `src/components/lab/`（实验台页面），只负责调度与展示；
- 支持自定义测试语句、数据集条数、方法参数 JSON，以及 target / attack / eval 三通道模型配置（默认复用设置里的 API Key）；模型下拉可选 **DeepSeek Flash / V4 Pro**，默认跟随聊天当前模型，三通道共用；
- 手机端参数面板与结果区改为单列纵向滚动，字段两列在窄屏自动堆叠，结果摘要允许换行；
- 逐条展示最终提示词、目标回复、判分结果与 ASR，可取消任务、导出结果；
- 实验台新增「多路赛跑」「变体赛跑」两个标签页（见 3.13）。可用方法：PAIR、TAP、GPTFuzzer、ReNeLLM、ICA、DeepInception、Jailbroken、Cipher、CodeChameleon、Multilingual（已用本地假模型冒烟通过；TAP 与 GPTFuzzer 的实际效果取决于评估模型能否返回可解析判分）；MJP 待适配；GCG / AutoDAN 依赖本地白盒模型，纯 API 环境不支持。详见 [`mcp-server/README.md`](../../mcp-server/README.md)；
- 数据集：安装 `datasets` 后可在线加载 AdvBench（520 条）/ HarmBench / StrongREJECT，默认走 `hf-mirror.com` 镜像，可用环境变量 `HF_ENDPOINT` 覆盖；未安装时回退到内置测试语句；
- 实验结果可「导出结果」保存为 JSON，也能「导入结果」回放之前的实验；判分成功的条目有「导入到聊天」按钮，会新建会话并把最终提示词填进输入框（模板里的 `{query}` 会替换成占位提示，先改再发）。
- 起步三步：`pip install datasets`（可选）→ `./mcp-server/run.sh` → `pnpm dev`，然后在侧栏「实验台」里连接并运行。连接报 403 时见 [`mcp-server/README.md`](../../mcp-server/README.md) 的故障排查（浏览器 Origin 白名单：dev、`file://` 的 `null`、线上域名；其他域名可用 `MCP_ALLOWED_ORIGINS` 追加）。

### 3.10 高级玩法：提示词预设、输入扰动、自动调参、输出整形与多路赛跑

输入栏使用响应式工具行：桌面端单行展开文字标签（模型、自动越狱、思考强度、联网搜索、输入扰动），模型与开关之间有一条细分隔线；小于 768px 时第一排除模型选择外收起为圆形图标并横向滚动，思维链 / 智能搜索 / 深度思考移到第二排并保留文字标签，和发送按钮那一排上下相邻（宽度够时直接同排），不再需要横向滑动去找功能。

设置 → **高级**（全部默认关闭，开箱行为与之前一致）：

| 设置项          | 作用                                  | 注意                                                                                  |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------- |
| 系统提示词预设  | 在默认的 v4.1 文档与 GODMODE 之间切换 | GODMODE 会整段替换 `system`，不再追加破限规则分块；仍可被自定义提示词覆盖             |
| 输入扰动        | 发送前改写命中的敏感触发词            | 输入框里看到的就是实际下发的文本，重发与续写沿用改写结果                              |
| 扰动技术 / 强度 | 8 种技术、3 档强度                    | L33tspeak、同形字、大小写、音近只影响拉丁字母；全角、细空格、零宽对中文同样有效       |
| 自动调参        | 按上下文选择采样参数                  | DeepSeek 的 Anthropic 兼容接口只接受 `temperature` 与 `top_p`，`top_k` 等参数不会下发 |
| 输出整形        | 去退让语气 / 直给 / 口语              | 只影响聊天显示与赛跑结果的复制，不改写本地保存的原文                                  |

- 触发词表是中英双语的（英文 60 余个、中文 90 余个），中文按子串匹配、英文按词边界匹配，见 `src/services/unrestricted/parseltongue.ts`；
- 输入框工具行新增「扰动」按钮，点开可以开关、切换技术、查看命中数量与实时改写预览；
- 实验台「越狱方法」页新增「先用扰动改写测试语句」，提交前会对自定义测试语句做同样的改写；
- 实验台新增「多路赛跑」页：选 5 套 L1B3RT4S 提示词组合并发调用（可混合 `deepseek-v4-pro` / `deepseek-flash`），逐条流式展示，按 100 分制综合分（篇幅 / 结构 / 反拒绝 / 直接性 / 相关性）标出胜出者，并能「用此组合开新会话」——把该组合的系统提示词设为自定义提示词、问题填进输入框；
- 引擎代码集中在 `src/services/unrestricted/`，移植自 [G0DM0D3](https://github.com/elder-plinius/G0DM0D3)，保留 AGPL-3.0 文件头与许可证副本（`COPYING-AGPL-3.0`）。

### 3.11 思考强度、上下文占用、会话统计与费用估算

- **思考强度**：输入框原来的「深度思考」开关换成 0–4 档滑轨（关闭 / 轻量 / 标准 / 深度 / 极致）。档位写进请求：`thinking: { type: "enabled", budget_tokens }` 与 `reasoning_effort`（low / medium / high / max）；服务端返回 400 且报错里含 reasoning / thinking / budget / effort 时，自动去掉强度参数、退回 `thinking: { type: "enabled" }` 重试一次，并提示已降级。
- **流式输出**：设置 → 模型新增开关，默认开启；关闭后不渲染中间态，等完整回复生成完再一次性显示。防撤回仍作用于最终内容：拒绝回复在「防撤回」开启时保留，关闭时丢弃。
- **上下文占用**：输入框右下角的圆环按模型窗口（1M）折算本轮请求的上下文（`input + cache_read + cache_creation`），60% 以上变琥珀色、85% 以上变红色；悬停可看具体数值、压缩阈值（窗口 80%，预留 64k 余量与输出空间）以及压缩后的等效占用与节省量。
- **会话统计**（输入框右侧「统计」按钮）：会话回合、步骤（回复 + 工具调用）、输出速度、首 token 平均、模型用时、缓存命中率，以及未缓存输入 / 缓存读取 / 缓存写入 / 输出四个 token 数；生成中还会显示本次生成的实时数据。
- **自动越狱**（输入框工具行开关）：开启后 `system` 换成 GODMODE + 深度指令，强制输入扰动（未单独选技术时用全角）、强制自动调参、跳过安全审核；被安全拒绝（`stop_reason: refusal` 或正文命中拒绝话术）且没有保留正文时，按 L1B3RT4S 组合依次自动重试两次，全部失败会提示停止（每次重试都是一次真实请求，会产生额外费用）。
- **回复评分**：每条回复可点赞 / 点踩，评分连同该轮的上下文类型与采样参数写入 AutoTune 的 EMA 画像，后续自动调参会参考你的反馈（数据只在本机）。
- **会话级提示词**：赛跑「用此组合开新会话」只作用于新会话，会话顶部有提示条可一键恢复默认，不再覆盖设置里的提示词预设；该提示词随会话保存在本机（IndexedDB），历史导出包里不含它。
- **费用估算**：按官方定价页（元 / 百万 tokens）估算，`deepseek-flash` 与 `deepseek-v4-pro` 分别计价（每条回复按自己的模型算，未知模型按 Flash 兜底），并区分高峰 / 空闲：北京时间工作日 9:00–12:00、14:00–18:00 为高峰（空闲价是高峰价的一半），可按「今天算节假日」整体切到空闲价；另外计入联网搜索 / 网页抓取（5 元 / 1000 次）、文档解析（1.5 元 / 1000 页，按文件大小估算页数）、语音合成（3 元 / 万字符，可关掉限时 5 折）与语音识别（0.78 元 / 小时）。

### 3.13 变体赛跑（实验台第三个标签页）

> 「多路赛跑」与「变体赛跑」直接调用 API，**不需要连接 MCP 后端**；只有「越狱方法」页需要本地 MCP。

把单文件版的 Parseltongue v4 搬进实验台：**33 种扰动技术**按档位（轻量 11 / 标准 22 / 重度 33）逐词改写问题，分批并发请求同一个模型，按综合分取最高分。

| 项          | 说明                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| 档位        | 轻量 11 种、标准 22 种、重度 33 种；技术顺序与上游一致                                                              |
| 采样轮换    | 每个变体轮换一组 temperature / top_p（11 组循环），与上游 `getParseltongueSamplingParams` 一致                      |
| 并发        | 每批 6 个、批内 100ms 错峰；领先分数 ≥65 提前收工                                                                   |
| 预算上限    | 按单次最坏花费预估可用请求数，实际花费达到预算后不再发起；费用按服务端上报用量结算                                  |
| 确认弹窗    | 首次开跑前确认请求数与最坏花费，可勾选「不再提示」永久关闭                                                          |
| 拒绝识别    | 协议 `stop_reason: refusal` 或正文命中拒绝话术都标记为被拒绝，不参与评分                                            |
| 导入 / 导出 | 「导出结果」保存 JSON（含实际使用的系统提示词），「导入结果」回放之前的赛跑；按 `type` 校验，拒绝其他页面的结果文件 |
| 接着聊      | 任意完成的结果可一键带进新会话：改写文本作为提问、回复作为回答，系统提示词挂在会话上，不覆盖设置                    |

中文适配：对中文触发词有效的是 `spaced / zwj / dotted / underscored / reversed / brackets / strikethrough / hyphenated` 等；`bubble / unicode / morse / pigLatin / mathBold` 一类只改拉丁字母，`fullwidth` 只平移 ASCII 可见字符。中文触发词按子串匹配，不依赖 `\b`。

### 3.15 分支到新对话

在侧栏会话菜单（⋯ → **分支到新对话**）或桌面端会话标题栏点「分支到新对话」，会把当前会话的可见分支复制成一个**全新会话**：

- 新会话 id 与所有消息 id 全部重新生成，原会话完全不受影响；
- 继承当前系统提示词（实验台组合）与压缩摘要；
- 新会话标题带「（分支）」后缀，之后两条线各自独立发展；
- 生成中、导入中或会话未加载时不可分支。

和消息级「分支切换」不同：后者在同一会话内保留回答版本，这里是在会话列表里开一条新线。

### 3.17 长期记忆与每日用量

**长期记忆**（设置 → 记忆）：

- 手动添加 / 编辑 / 启停 / 删除 / 清空，启用的条目会注入每次请求的 `system`；
- 打开「自动提炼」后，每轮结束会额外调用一次 Flash，把稳定事实、身份、长期偏好写成 JSON 操作并更新列表（会产生少量费用，默认关闭）；
- 记忆只保存在本机，历史导出包不包含；与网状记忆库联动，启用的条目会同步成 `saved` 节点。

**每日用量与提醒**（设置 → 通用）：

- 统计当天 `input + cache_read + cache_creation + output` 的 token 与按模型 / 峰谷价估算的费用；
- 可设置每日 Token 上限与费用上限，达到后当天只提醒一次（toast），不会阻止请求；
- 统计弹窗的会话指标新增「今日 Token / 今日费用」，可随时重置今日计数。

### 3.18 网状记忆库（移植自 Operit）

设置 → 记忆 → **网状记忆库**：

- 节点包含标题、正文、标签、重要度、可信度；新增节点时按本地哈希向量的余弦相似度自动连边（最多 3 条，权重为相似度）；
- 检索同时计算关键词、标签、向量与关联边扩散分数，四项权重可分别调整；相关度阈值与每次注入条数可调；
- 向量维度可选 64 / 128 / 256 / 384 / 768，默认 256；向量在浏览器本地生成，不调用外部 embedding 服务；
- 「搜索调试」展示每个候选的关键词 / 标签 / 向量 / 关联分、总分与是否过阈值，并统计节点数、边数、命中数与边遍历次数；
- 请求时按当前问题检索 Top N，与长期记忆一起注入 `system`；没有命中时不会注入；
- 记忆库支持 JSON 导入导出，可选择「合并」（按内容去重）或「覆盖」；归档包含长期记忆与节点/边；
- 「关系图」把节点与带权重的边画出来，点击节点查看正文与标签；手机端保持可读尺寸并横向滚动；
- 直接展示当前向量维度、节点数、平均度与 Float32 预计占用；搜索调试额外显示维度、查询词数量与最高分；
- 聊天统计与输入框上下文圆环会显示记忆库节点/边/维度/上次注入条数；恢复默认设置会重置检索参数与每日提醒，但保留已保存的记忆数据；
- 手机端权重改为单列、搜索调试表格横向滚动，节点与标签自动换行。

### 3.19 位置：清除、自定义与星际位置

设置 → 通用 → 位置：

- 已选择位置时出现「清除位置」按钮，可恢复为不注入位置；
- 下拉框旁新增自定义输入框，可手写任意地点（如「巴黎」「南极中山站」）；回车或失焦生效；
- 自定义位置优先于行政区与特殊位置，直接写入 `latest_reminder` 的位置字段；
- 特殊位置：空间站（卫星 / 空间站）、月球（月之明面 / 月之暗面）、火星（时空管理中心）；
- 特殊位置覆盖行政区选择；自定义位置与特殊位置都只影响 `latest_reminder`，不改变天气、联网搜索或服务端区域判断。

### 3.20 搜索投毒

设置 → 搜索投毒。这个分组把客户端能控制的搜索输入全部开放出来：

| 能力           | 行为                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 当前时间       | 用 `datetime-local` 指定注入给模型的日期与星期；留空使用真实时间                           |
| 知识截止       | 声明模型数据库 / 训练数据截止日期；留空不声明                                              |
| 接管联网搜索   | 有自定义结果时不声明 `deepseek_web_search`，模型只看到过滤后的本地结果；关闭则保留真实搜索 |
| 结果替换       | 关键字或正则，按 URL / 标题 / 摘要 / 全部替换；正则支持 `$1` 捕获组                        |
| 黑名单         | 命中任意字段的结果从界面、导出和模型上下文中移除；自动接管搜索                             |
| 强制自定义结果 | 无论真实搜索是否命中，都把自定义结果注入模型并显示为搜索结果                               |
| 白名单         | 只保留命中白名单的自定义结果；服务端结果全部不返回                                         |

- 规则引擎在 [`src/services/searchPoison.ts`](../../src/services/searchPoison.ts)：替换、黑名单、白名单都先于注入执行；最多 50 条规则、20 条自定义结果；
- 自定义结果会进入 `system`，长内容会增加输入 token；单条摘要上限 4000 字符；
- 接管模式：请求体 `tools` 只保留 `deepseek_read_url`，`system` 末尾追加 `[LOCAL SEARCH LAYER]` 分块，自定义结果同时补一个「投毒搜索」步骤，显示在回复时间线里，底部网页汇总可打开；
- 非接管模式：仍使用服务端搜索；结果块进入客户端时替换 / 拉黑，正文引用角标同步替换 / 过滤，但服务端本轮已经消费过的结果无法撤回；
- 自定义时间写入 `latest_reminder` 的日期、星期与位置，知识截止和搜索结果写入 `system`；界面时间、计费、天气、定位不变；
- 与防撤回、流式输出兼容：只影响请求上下文和结果展示，拒绝内容保留逻辑不变；关闭流式时仍在结束后一次性显示投毒步骤；
- 所有配置存 `chat-demo:search-poison`，恢复默认设置会重置；接管搜索时真实联网搜索不会执行，需要真实搜索请关闭接管或清空黑名单 / 白名单。

### 3.21 附件投毒

设置 → 附件投毒。默认关闭；启用后在上传前用浏览器本地处理改写附件，模型读取附件时会看到你填写的文本。

| 方式                 | 适用文件                            | 说明                                                       |
| -------------------- | ----------------------------------- | ---------------------------------------------------------- |
| 文本正文注入         | TXT / MD / CSV / 代码 / HTML / JSON | 在正文前或后插入带 `[ATTACHMENT NOTE]` 标记的文本          |
| DOCX 正文注入        | `.docx`                             | 解压后在 `word/document.xml` 的 body 末尾追加段落          |
| 图片文字覆盖         | PNG / JPG / WebP / GIF 等位图       | 在图片顶部或底部绘制文字面板，模型通过视觉 / OCR 读取      |
| 图片元数据（实验性） | JPEG / PNG                          | 写入 JPEG COM 或 PNG tEXt 元数据，部分解析器会读到         |
| 文件尾附加（实验性） | PDF / 未知二进制                    | 在文件末尾追加文本；ZIP 类 Office 文件自动跳过             |
| 文件名注入           | 所有格式                            | 把内容前 40 字写进上传文件名，模型能看到文件名时生效       |
| 伴随文本附件         | PDF / Office / 任意格式             | 额外生成一个 `.txt` 随消息发送，最可靠，但占用一个附件名额 |

- 方式可多选，按文件类型自动选择实际生效的处理；处理失败时回退为原文件，不阻断上传；
- 内容上限 4000 字符，统一带 `[ATTACHMENT NOTE]` 标记；文字、DOCX 与图片文字面板可放在正文前或后；
- 原始文件仍保存在 IndexedDB，上传的是处理后的副本；重新上传时可以按新配置重新投毒；
- 修改设置后，下一次发送会按当前配置重新上传输入框里有本地原件的附件；已发送的历史附件不会重写，没有本地原件的导入附件保持原样；
- 启用 / 关闭或切换伴随附件时，输入框里的原附件会立即重新上传；伴随文本附件在启用 / 关闭时自动同步，修改内容后请重新选择附件；
- 恢复默认设置会关闭并清空附件投毒配置，并移除草稿中自动生成的伴随文本附件；
- 图片文字覆盖会重新编码图片，GIF / 动图会变成静态图，GIF / BMP 等可能转成 PNG；PDF / Office 建议优先使用伴随文本附件。

### 3.22 自定义思维链

设置 → **思维链**。默认关闭；打开后把预先写好的推理步骤作为独立 system 分块注入每次请求，让模型按你定义的顺序推理，而不是只靠一句「请逐步思考」。

正文自带一份默认提示词（内置的 `thinking_prompt`）：首次使用、点「填入默认提示词」、恢复默认设置都会用它，仍可在设置页或输入栏卡片里自由改写。

| 深度思考       | 注入内容                  | 行为                                                                     | 稳定性   |
| -------------- | ------------------------- | ------------------------------------------------------------------------ | -------- |
| 关闭（0 档）   | `[自定义思维链]`          | 模型在内部按步骤作答；回复上方显示「已注入思维链」卡片，随后显示最终回答 | 常规能力 |
| 开启（1-4 档） | `[自定义思维链 · 实验性]` | 作为服务端思考的引导；服务端可能忽略、调整或重写这些步骤                 | 实验性   |

- 输入栏重新排版：第一排为模型 / 自动越狱 / 扰动，第二排为思维链 / 智能搜索 / 深度思考；手机端仍是一行横向滚动；
- 输入栏「思维链」按钮改为卡片入口，与设置页共用同一份配置：可直接开关、编辑、填入示例、清空，或点「打开设置」查看完整说明与 system 预览；
- **关闭深度思考时，回复上方会显示「已注入思维链」卡片**（默认展开、可折叠），内容是这一轮实际写入 system 的步骤，不再只显示最终回答；它不是服务端返回的 thinking，而是用户预设的推理步骤；
- 开启深度思考时不重复显示该卡片，服务端 thinking 照常展示；思维链仍作为实验性引导注入；
- 每条回复保存本轮注入快照：续写沿用原快照，重新生成读取当前设置，避免中途修改设置导致同一轮前后不一致；
- 思维链放在 Persona / 破限规则之后、长期记忆与搜索上下文之前；首轮请求同时带标题生成，也会注入，否则新会话第一条回复不会生效；
- 正文上限 4000 字符；只保存在本机 `chat-demo:custom-cot` 与 `chat-demo:custom-cot-enabled`，每轮都会增加输入 token；
- 只修改 `system`，不改消息结构：流式 / 非流式、续写、重新生成、标题生成、附件、搜索投毒与历史导入导出都保持兼容。

### 3.23 统计、图表与上下文管理

**位置：** 设置 → **统计**，以及输入栏的会话统计弹窗。

- **用量账本**（`usageLedger`）：每轮请求结束时按「日 / 模型」记账，记录未缓存输入、缓存读取、缓存写入、输出、预估费用、请求次数与联网搜索次数；账本在 localStorage 里保留最近 400 天，只存聚合数字、不含对话正文，和只管今天（用来触发额度提醒）的每日用量分开。
- **范围切换**：今天 / 7 天 / 30 天；中间没有请求的日期补 0，保证图表坐标连续。
- **KPI 区**：总 token、预估费用、缓存命中率、请求次数、有用量的天数、联网搜索次数。
- **每日趋势柱状图**：可切换指标——token（右柱为费用）、费用、请求数；每天一对柱子，悬停显示当天明细。
- **活跃热力图**：最近 8 周，每天一格，按窗口内最忙的一天分四档强度。
- **小时分布**：把所选范围内 24 小时的请求数画在一根轴上，能看出自己一般什么时候在聊；下方注明最忙的一小时。
- **输入构成环**：未命中缓存输入 / 命中缓存输入 / 缓存写入 / 输出，各带 token 与占比，一眼看出费用主要来自哪一段。
- **按模型拆分**：所选范围内每个模型的请求数、token 与费用；未知模型按 Flash 单价估算。
- **会话排行**：范围内按 token 排序的会话，带费用与请求数；点「打开」直接跳到该会话（会话已删除时按钮置灰）。
- **附加用量**：联网搜索、文档解析页数、语音合成字符与语音识别秒数——token 统计覆盖不到的计费项。
- **上下文统计管理**：当前会话上下文对照模型窗口与压缩阈值，下面是记录中的会话表格，含上下文体量、窗口占比与最近请求时间；可清除单条、清空全部记录、导出 JSON / CSV、清空用量账本。
- **账本 v2**：每天记录里增加 24 小时直方图与会话维度拆分；旧版 v1 账本读取时按缺省值补齐，升级不需要迁移脚本；损坏的 JSON 当作空账本处理，不会带崩页面。
- **上下文分类**：把当前会话最近一轮请求拆成系统提示词 / 工具定义 / 用户消息 / 模型回复 / 模型思考 / 工具调用 / 工具结果 / 附件，各自给出估算 token 与占比；估算按字符权重，准确用量仍以 KPI 区服务端上报的数字为准。
- **计费口径**：按模型列出未命中 / 命中 / 输出的单价（元 / 百万 token），并摊开联网搜索、文档解析、语音合成与识别的单价，标注工作日高峰翻倍规则，账单对不上时可以直接对照。
- **服务端搜索免费开关**：按官方新政策（北京时间 2026-11-18 12:00 起），模型调用触发的服务端搜索、网页抓取不再计费，只按 Token 计费；开关默认开启。关闭后按旧规则（5 元 / 1000 次）估算，便于对旧账单。

**输入栏会话统计弹窗**新增本次会话输出趋势（迷你折线 + 最新 / 平均 / 最长）、用于横向对比的「最近 7 天用量」、输入构成环、附加用量卡（搜索 / 抓取 / 解析文件与页数 / 语音字符 / 语音秒数），以及带剩余窗口与压缩阈值的上下文压力表；底部可直接跳到设置 → 统计。

**API Key 脱敏**：越狱实验台不再渲染完整 Key，改成 `sk-****` 加末四位，并提供「在设置中修改」跳到设置 → 数据管理，和设置页自己保存 Key 的掩码展示保持一致。

> 这些工具的实际下发范围还受输入栏「聊天模式」控制：仅聊天模式一个都不发，网页 Agent 模式发浏览器 + 工作区，PTC / 创造模式再加上 NanoVM。详见 3.27。

### 3.24 浏览器 Agent 工具

**位置：** 设置 → **浏览器工具**。移植自 `DeepSeek-Agent` 的 browser / widget 工具，只保留浏览器能力；MCP 工具、子 Agent 与工作区（桌面端）工具按要求没有移植。

| 工具           | 做什么                                                                | 说明                             |
| -------------- | --------------------------------------------------------------------- | -------------------------------- |
| 时间日期       | 本地化日期、ISO 时间、星期与时区偏移，可指定 IANA 时区                | 只读，不联网                     |
| 网络定位       | 经纬度、精度与逆地理得到的城市名                                      | 浏览器会弹定位授权               |
| 天气查询       | Open-Meteo 当前天气 + 1–7 天预报，可传城市名或经纬度                  | 无需 API Key；都不传时尝试定位   |
| 发送通知       | 系统桌面通知                                                          | 首次使用请求权限                 |
| 读取剪贴板     | 返回剪贴板纯文本                                                      | 执行前需要确认                   |
| 写入剪贴板     | 把文本写进剪贴板                                                      | 会写入本机                       |
| 抓取网页       | 抓取页面正文并转纯文本，限制字符数                                    | 受目标站点 CORS 限制             |
| 生成文件       | 产出可预览、可下载的文件（Markdown / HTML / CSV / JSON / SVG / 代码） | 执行前需要确认；只存在本机       |
| 打开链接       | 在新标签页打开 URL                                                    | 可能被弹窗策略拦截               |
| 生成可视化组件 | 在沙箱 iframe 里渲染自包含的可交互 HTML                               | 沙箱没有同源权限，读不到聊天页面 |

- **每一项都能单独开关。** 主开关关闭时一个工具都不下发；关掉某一项后模型完全看不到它，若模型凭历史记忆调用，执行阶段会直接拒绝并说明原因，不会真的执行。
- **工具往返发生在同一条回复里**：模型给出 `tool_use`，页面本地执行，结果作为 `tool_result` 回传后继续生成（最多 4 轮）。每一轮都是一次真实请求，token 按轮计费。
- **工具卡片**展示工具名、参数摘要、状态与耗时，展开可看原始参数与结果；产物在卡片下方：文件给预览与下载，组件直接在沙箱 iframe 里渲染，可运行脚本但读不到聊天页面数据。
- **执行确认**：读取剪贴板与生成文件会先弹窗展示完整参数，可勾选「本次会话都允许」；拒绝会以错误结果回传给模型，回复不会卡住。
- **环境检测**：通知、定位、剪贴板在当前浏览器不可用时会标注并禁用对应开关，而不是等到调用时才失败。
- 全部在本机完成：工具结果与产物随回复保存在本地，历史导出包里不含这些字段。

### 3.25 虚拟工作区

**位置：** 设置 → **工作区**。完全活在浏览器存储里的文件库，不需要后端也不碰真实磁盘，让 Agent 有一个可以跨对话长期保存笔记、报告与生成文件的地方。

| 组成        | 行为                                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件        | 任意格式：文本可新建 / 在线编辑（改路径即重命名），图片、PDF、压缩包等二进制按原始字节保存；均可删除、预览、单文件下载                                                                  |
| 限制        | 按字节计算：OPFS 模式根据浏览器实际配额动态放大（最多用 80%，上限 64GB 总量 / 256MB 单文件），localStorage 模式受浏览器 5–10MB 限制、单文件软上限 4MB；设置页显示实时占用与当前生效上限 |
| 导入 / 导出 | 「导入文件」接受任意格式（可多选）；「导出 ZIP / 导入工作区」整包往返，二进制原样保留；旧版 JSON 备份仍可导入。归档导入可选合并（同名覆盖）或覆盖全部                                   |
| 路径        | 只允许相对路径，拒绝 `..`、绝对路径与盘符，避免出现奇怪的键名                                                                                                                           |
| 工作区工具  | `list_workspace`、`read_workspace_file`、`write_workspace_file`、`diff_workspace_file`、`delete_workspace_file`；写入与删除需要确认，diff 以文件进入工作区时的内容为基线                |
| 存储方式    | 浏览器本地存储（localStorage，默认）或 **OPFS 真文件系统**，可在设置里随时切换，切换时把现有文件整体复制到新后端                                                                        |
| 持久化      | 可点「申请持久化存储」调用 `navigator.storage.persist()`，并展示授权状态、已用空间与配额；降低浏览器在空间不足时清理数据的风险                                                          |
| 默认值      | **关闭**。Agent 主开关与工作区开关都从关闭开始，全新安装不会下发任何工具                                                                                                                |

- 关掉工作区后，即使 Agent 主开关打开，模型也看不到任何工作区工具；若模型凭历史调用，执行阶段会直接拒绝。
- 这里的内容不会上传。历史导出包不含工作区，清浏览器数据前请自行导出备份。

### 3.26 NanoVM Slim（浏览器里的 WASM shell）

**位置：** 侧栏底部 **NanoVM Slim**（在「实验台」「设置」上方）打开终端；控制台在 设置 → **NanoVM Slim**。

一个跑在页面里的轻量 POSIX 环境：WASM Shell Engine + busybox 风格命令集，不需要后端、不碰真实磁盘，文件都存在浏览器里。

| 组成       | 行为                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 引擎       | 首次执行命令（或点开终端且「首次使用时加载引擎」为开）时才动态加载引擎 chunk，首屏不下载；引擎按「内存分配」实例化 WASM 线性内存，管道缓冲走这块内存，超配额返回 `Cannot allocate memory`                                                                                                                                                                                                                                                                                                                                                                                                      |
| 终端       | 桌面端停靠在聊天右侧（默认 420px，可拖拽宽度；关掉「右侧常驻」改成浮层）；手机端是底部面板，键盘弹出时自动填满键盘上方，可拖拽高度、可全屏；支持多标签、↑↓ 翻历史、Ctrl+C 中断                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 切换输入法 | 手机端输入行的键盘按钮可以呼出系统输入法选择器（APK 里走原生 `InputMethodManager`），换键盘不用离开终端；纯浏览器没有这个能力，会提示用系统快捷键                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 重置       | 桌面头部与手机工具条都有红色「重置」：二次确认后清空虚拟机里的全部文件并重启引擎（设置里的控制台同样可以重置）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| busybox    | 130 个内置命令：文件与系统（`ls cat cp mv rm mkdir rmdir touch ln stat chmod du df ps free env export which` …）、文本（`grep sed awk sort uniq cut tr wc nl rev tac paste find xargs tee` …）、字节与数据（`sha512sum strings hexdump xxd od column fold expand unexpand numfmt cmp base32`、`jq` 子集、`zip unzip split shuf join comm`、`basename dirname realpath readlink mktemp nproc timeout`、开发工具 `patch bc expr tree fmt time uuid getopt tsort envsubst dotenv sponge`）、归档与校验（`tar gzip gunzip sha256sum md5sum base64 cksum diff`）、网络（`curl wget`，受 CORS 限制） |
| 联网       | `wget` / `curl` / `ping` 自动补 `https://`；**APK 走内置代理**（本地 127.0.0.1 反向代理，用 Android 的 `HttpURLConnection` 真发请求，不受 WebView 的 CORS 限制），普通浏览器直连只能访问允许跨域的站点；设置 → NanoVM Slim → **联网代理** 可以切直连或填自己的代理前缀（支持 `{url}` 占位）                                                                                                                                                                                                                                                                                                    |
| 虚拟网络   | 浏览器里没有 socket，所以 `vm serve <端口> <命令>` 用 **CGI 模型**注册服务：`curl http://127.0.0.1:<端口>/` 时把命令跑一次（环境变量给请求、stdin 给 body、stdout 按 CGI 格式回响应）；`serve <端口> [目录]` 起静态站、`vm serve --ws` 注册 WebSocket（`wscat` 单消息）；Node 的 `http` / `ws` 与 Python 的 `nanovm_serve`（Flask 等 WSGI 应用）都挂在这套网络上。没有常驻进程与长连接，大响应会整体缓冲                                                                                                                                                                                       |
| 按需工具链 | 运行时：Python 3（Pyodide，约 12MB）、Node.js 兼容运行时（无需下载）、Lua 5.4（wasmoon，约 0.4MB）、SQLite 3（sql.js，约 1.3MB）；构建工具：esbuild（约 12MB）、TypeScript（tsc，约 9MB）、Sass（约 5.8MB）、Terser（约 1.1MB）、Prettier（约 2MB）、GNU make（内置）；工具：Git（内置实现）                                                                                                                                                                                                                                                                                                   |
| 包管理     | `vm install python`、`vm uninstall python`、`vm list`、`vm info`、`vm mem`、`vm df`；安装进度直接打在终端里，Agent 也能调用                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 控制台     | 开关（启用、允许模型调用、首次加载、桌面常驻）、内存与虚拟磁盘配额、命令超时、引擎状态、存储位置与用量、镜像导入导出（zip）、重置；工具链按「运行时 / 构建工具 / 命令行工具」分组，卡片显示体积、状态、版本与示例命令（可点击复制）                                                                                                                                                                                                                                                                                                                                                            |
| 存储       | 虚拟磁盘落在 OPFS（`chat-demo-nanovm`），不支持时回落 localStorage；导出的 zip 含 manifest 与完整文件树，可在另一台设备导入                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Agent 工具 | `nanovm_shell`（执行命令，需确认）、`nanovm_ls`（只读列文件）、`nanovm_install`（装运行时，需确认）；默认**关闭**，总开关或「允许模型调用 Shell」任一关闭时模型完全看不到这三个工具                                                                                                                                                                                                                                                                                                                                                                                                            |
| 默认值     | 启用 NanoVM Slim，**允许模型调用关闭**；内存 128MB、磁盘 64MB、命令超时 15 秒                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

- 终端里的命令不联网（例外：`vm install`、`curl` / `wget`，以及聊天本身的 API 请求）。
- 中文注释、UTF-8 文件名、多行输出、管道与重定向都支持；`&` 后台进程不保留（没有作业控制）。
- 第一次安装 Python 需要联网，之后从本机缓存加载；Node.js 与 Git 是内置实现，离线可用。

### 3.27 聊天模式（仅聊天 / 网页 Agent / PTC / 创造）

**位置：** 输入栏「思维链」左边的模式胶囊，样式与模型切换一致，点开是四项菜单。

模式只决定「这一轮把哪些客户端工具下发给模型」，是在设置开关之上再加的一道限制：设置里关掉的工具，模式允许也不会发。

| 模式           | 下发的工具                                                                | 客户端工具往返上限 | 特有行为                                                                                                         |
| -------------- | ------------------------------------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **仅聊天**     | 只有服务端工具（读链接 / 联网搜索），浏览器、工作区、虚拟机工具一个都不发 | 4                  | 长期记忆、搜索投毒、自定义思维链照常生效                                                                         |
| **网页 Agent** | 浏览器工具 + 虚拟工作区工具                                               | 8                  | 抓网页、通知、剪贴板、工作区读写                                                                                 |

| **创造**       | 同 PTC                                                                    | 24                 | 允许模型 `vm install python`、把脚本写进 `/usr/bin` 并 `chmod +x` 当成新命令；虚拟机写操作与安装**不再逐次确认** |

- 模型凭历史记忆调用当前模式不允许的工具时，执行阶段会拦下并提示「当前聊天模式不允许使用工具」。
- 默认模式是**网页 Agent**，与开启 Agent 之后的原有行为一致；选择记在 `chat-demo:chat-mode`。
- 菜单里会提示「当前设置：浏览器工具主开关已关闭 / 工作区开关已关闭 / NanoVM 未允许」，避免选了模式却以为已经生效。

### 3.29 WebVM（CheerpX）

**位置：** 侧栏「WebVM」，或终端面板顶部的「NanoVM Slim / WebVM」切换器；设置 → **虚拟机** 下方的 WebVM 卡片。

**它是什么：** 第二个终端跑的不是模拟 shell，而是 CheerpX 提供的 x86 虚拟化 Debian 10。CheerpX 把 x86 指令 JIT 成 WebAssembly，在浏览器里直接执行真实的 Linux 二进制；根文件系统是从 `disks.webvm.io` 流式读取的 ext2 镜像，改动写进 IndexedDB 覆盖层。镜像自带 bash、coreutils、gcc / g++、Python 3、Node.js、Ruby、Perl、Lua 5.3 / LuaJIT、make、git、vim、nano、curl、wget 等环境，打开就能编译 C/C++、跑 Python / Node 脚本。

| 能力         | 行为                                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行         | 首次打开从 Leaning CDN 加载 CheerpX 1.4.0（约 1MB），并流式读取约 2GB 的 Debian 镜像块；之后从 IndexedDB 覆盖层缓存启动，磁盘改动刷新页面后仍在         |
| 与 NanoVM    | 两个实例同时存在；切换只换视图，WASM 引擎、CheerpX 进程、终端滚动历史与文件都不销毁。桌面停靠和手机底部面板都支持                                    |
| 终端         | xterm.js + 真实 PTY：方向键、Tab、Ctrl+C / Ctrl+D、vim、top 等全屏程序、IME 中文输入都可用；底部工具条有 Esc / Tab / 方向键 / 键盘 / 导入 / 导出 / 环境检测 |
| 跨源隔离     | CheerpX 需要 SharedArrayBuffer，即 COOP/COEP。静态站点第一次启用时注册 `coi-sw.js` 并刷新一次；Android WebView 不支持跨源隔离，APK 内会提示改用手机 Chrome / 桌面浏览器 |
| 镜像         | 默认 Debian 10（2026-06 镜像），可切到 2023 镜像或填自定义 `wss://` / `https://` / 同源 ext2 地址；不同镜像使用独立的覆盖层                               |
| 导入         | 文件写进只读 DataDevice 的 `/data`，再在 VM 里 `cp` 到 `/home/user/imports`；一次最多 50 个文件、20MB                                                    |
| 导出         | 在 VM 里 `tar czf - -C /home/user . \| base64 -w0`，浏览器捕获并下载 `webvm-home.tar.gz`；上限 32MB                                                     |
| 模型调用     | 新增 `webvm_shell` / `webvm_ls` / `webvm_status` 三个工具；与 NanoVM 工具同一分组（PTC / 创造模式才下发），执行前确认，创造模式自动放行               |
| 检测         | 设置卡片里的「检测环境」会在 VM 里跑 `uname`、`/etc/debian_version` 与 24 个命令的 `command -v`，直接显示哪些语言 / 工具存在                            |

- **为什么不能用 `cx.run()` 跑模型命令：** CheerpX 的 Linux 只有一个控制台。再起一个进程虽然能输出，但它退出后交互式 bash 的 stdin 不再回来，用户之后敲什么都没反应。所以 WebVM 的模型命令与导入导出都写到 `/data/agent_xxx.sh`，在**现有 shell** 里用 `timeout N bash /data/...` 执行，并用开始 / 结束标记框住输出。
- **并发与超时：** 模型命令串行执行，单次工具上限 5 分钟（首次启动要等镜像块）；普通命令 30–60 秒。超时只保证工具返回，已启动的命令仍可能继续跑完。
- **网络：** 默认不配置网络（CheerpX 的联网需要 Tailscale 登录），因此 WebVM 里没有 `apt install`；镜像已经预装常用环境。需要联网时请在自定义镜像里自带工具，或改用 NanoVM 的虚拟网络。
