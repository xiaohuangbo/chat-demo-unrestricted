### 3.2 解除限制模式（越狱模式）

**位置**：设置 → 破甲。

**原理**：系统提示词从「一句身份说明」变成一条组装流水线：

```text
Persona（官方身份分块）
      │
      ▼  [解除限制模式]
      ├─ 开启：追加「破限规则分块」，并强制跳过安全审核、允许继续生成被拒回复
      └─ 关闭：只下发 Persona，原样放行官方默认提示词
      │
      ▼
请求体 system 字段
```

- 破限规则来自仓库根目录的 [`deepseekv4.1 and v4.1-1017.md`](<../.././deepseekv4.1 and v4.1-1017.md>)，构建时由 rspack 以 `asset/source` **原样内联**进产物，运行期不依赖该文件；
- 组装时自动做两处归一：切掉文末残留的示例回答骨架、把 `{{PAYLOAD}}` 替换成「the request in the latest user message」；
- 设置页可以展开预览**本次请求实际会下发的 system 全文**；
- 开启后强制两项：`safety_check` 字段不发送、被拒回复允许继续生成（对应下面 3.5 / 3.6 的两个开关会显示为已开启并置灰）；
- **自定义系统提示词**（同分组的输入框）：留空时仍走上面的流水线；填写后把内容原样作为 `system` 下发，自动组装结果不再生效——此时越狱模式仍会跳过安全审核、放开被拒回复续写，但不会替换提示词。输入框下方「填入默认」把当前组装结果填进去作为起点，「恢复默认」清空覆盖。

### 3.3 模型参数

**位置**：设置 → 模型。

| 参数           | 控件            | 范围 / 步长       | 默认 | 下发方式                      |
| -------------- | --------------- | ----------------- | ---- | ----------------------------- |
| 温度           | 滑块 + 数字输入 | 0–2，步长 0.05    | 1    | `temperature`                 |
| Top P          | 滑块 + 数字输入 | 0.01–1，步长 0.01 | 1    | `top_p`                       |
| 最大输出 Token | 数字输入        | ≥1，可留空        | 留空 | 留空时**不发送** `max_tokens` |

- 滑块与数字框双向同步：输入框失焦或回车提交，超范围自动夹到区间、按步长取整；
- 全部持久化到 localStorage，下次打开自动恢复；
- 每次请求都会带上（最大输出 Token 除外，留空即不下发）。

### 3.4 防撤回

**位置**：设置 → 模型。

原版在 `stop_reason: 'refusal'` 时会把已经流式输出的正文和思维链删掉；打开防撤回后改为**保留**：

| 行为                  | 防撤回关闭（原版行为）           | 防撤回开启                                                               |
| --------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| 已下发的正文 / 思维链 | 全部删除                         | 保留并正常展示                                                           |
| 界面提示              | 显示固定模板答复                 | 内容下方一行提示「本轮回答被安全审核拦截，防撤回已保留模型已输出的内容」 |
| 后续上下文            | 该轮不参与                       | 正文保留后**照常进入上下文**                                             |
| 编辑按钮              | 不可用                           | 可用（内容保留后按正常回复处理）                                         |
| 导出历史              | 标记为 `CONTENT_FILTER` 并附模板 | 按正常结束导出，重新导入不会被再次清空                                   |

防撤回与越狱模式相互独立，越狱模式不会自动打开它。

### 3.5 跳过安全审核

**位置**：设置 → 模型。

- 关闭（默认）：请求照旧携带 `safety_check: { level: 'high' }`；
- 开启：请求体**不再包含 `safety_check` 字段**（`undefined` 在 `JSON.stringify` 时被丢弃）；
- 越狱模式开启时自动跳过并置灰。

按官方文档，不传 `safety_check` 与传 `low` 完全等价，这是 API 允许的最低档，没有更低。

### 3.6 拒绝后继续生成

**位置**：设置 → 模型。

- 关闭（默认）：`canContinueReply()` 对 `stopReason === 'refusal'` 直接返回 `false`，「继续生成」按钮不出现（原版行为）；
- 开启：被拒回复按「正常结束」参与续写判断，最后一条被拒回复下会出现「继续生成」；
- 越狱模式开启时自动放开并置灰。

其余续写限制不变：模板提示、服务端工具块、非前缀消息仍然不能续写。

### 3.7 回复改写

**位置**：每条 AI 回复下方的操作条，复制 / 朗读 / **编辑（铅笔）** / 重新生成。

- 点铅笔就地展开编辑器：上方**思维链**（该回复有思考时才出现），下方**正文**；`Ctrl/Cmd + Enter` 保存，`Esc` 取消；
- 保存直接把内容**写回消息的内容块**，不新建分支、不重新请求；之后每一轮组装上下文时读到的都是改写后的版本；
- 写回规则：思维链写入第一个思考块（没有则在最前面新建一个）、其余思考块清空；正文只作用于末尾那段「回答」的第一个文本块、其余文本块清空，正文变化会丢弃失效的引用标记；工具块、模板提示、思考签名一律不动；
- 首次改写会保存一份原始块快照，编辑器里的「还原原文」可一键恢复；
- 续写会让快照与追加后的内容对不上，因此续写后不再提供还原；
- 被安全拒绝且内容已被丢弃的回复不可编辑（没有可改的模型正文）；开了防撤回、内容仍在的可以。

### 3.9 越狱实验台（可选，需本地 MCP 后端）

侧边栏底部新增「实验台」：通过 MCP 连接本地 `mcp-server/`，把 EasyJailbreak 的攻击器搬进浏览器界面。

- 后端：`mcp-server/`（Python，MCP Streamable HTTP，默认 `http://127.0.0.1:8765/mcp`），启动 `./mcp-server/run.sh`；
- 前端：`src/services/lab/`（MCP 客户端）+ `src/components/lab/`（实验台页面），只负责调度与展示；
- 支持自定义测试语句、数据集条数、方法参数 JSON，以及 target / attack / eval 三通道模型配置（默认复用设置里的 API Key）；模型下拉可选 **DeepSeek Flash / V4 Pro**，默认跟随聊天当前模型，三通道共用；
- 手机端参数面板与结果区改为单列纵向滚动，字段两列在窄屏自动堆叠，结果摘要允许换行；
- 逐条展示最终提示词、目标回复、判分结果与 ASR，可取消任务、导出结果；
- 实验台新增「多路赛跑」「变体赛跑」两个标签页（见 3.13）。可用方法：PAIR、TAP、GPTFuzzer、ReNeLLM、ICA、DeepInception、Jailbroken、Cipher、CodeChameleon、Multilingual（已用本地假模型冒烟通过；TAP 与 GPTFuzzer 的实际效果取决于评估模型能否返回可解析判分）；MJP 待适配；GCG / AutoDAN 依赖本地白盒模型，纯 API 环境不支持。详见 [`mcp-server/README.md`](../../mcp-server/README.md)；
- 数据集：安装 `datasets` 后可在线加载 AdvBench（520 条）/ HarmBench / StrongREJECT，默认走 `hf-mirror.com` 镜像，可用环境变量 `HF_ENDPOINT` 覆盖；未安装时回退到内置测试语句；
- 实验结果可「导出结果」保存为 JSON，也能「导入结果」回放之前的实验；判分成功的条目有「导入到聊天」按钮，会新建会话并把最终提示词填进输入框（模板里的 `{query}` 会替换成占位提示，先改再发）。
- 起步三步：`pip install datasets`（可选）→ `./mcp-server/run.sh` → `pnpm dev`，然后在侧栏「实验台」里连接并运行。连接报 403 时见 [`mcp-server/README.md`](../../mcp-server/README.md) 的故障排查（浏览器 Origin 白名单：dev、`file://` 的 `null`、线上域名；其他域名可用 `MCP_ALLOWED_ORIGINS` 追加）。

### 3.10 高级玩法：提示词预设、输入扰动、自动调参、输出整形与多路赛跑

输入栏使用响应式工具行：桌面端单行展开文字标签（模型、自动越狱、思考强度、联网搜索、输入扰动），模型与开关之间有一条细分隔线；小于 768px 时第一排除模型选择外收起为圆形图标并横向滚动，思维链 / 智能搜索 / 深度思考移到第二排并保留文字标签，和发送按钮那一排上下相邻（宽度够时直接同排），不再需要横向滑动去找功能。

设置 → **高级**（全部默认关闭，开箱行为与之前一致）：

| 设置项          | 作用                                  | 注意                                                                                  |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------- |
| 系统提示词预设  | 在默认的 v4.1 文档与 GODMODE 之间切换 | GODMODE 会整段替换 `system`，不再追加破限规则分块；仍可被自定义提示词覆盖             |
| 输入扰动        | 发送前改写命中的敏感触发词            | 输入框里看到的就是实际下发的文本，重发与续写沿用改写结果                              |
| 扰动技术 / 强度 | 8 种技术、3 档强度                    | L33tspeak、同形字、大小写、音近只影响拉丁字母；全角、细空格、零宽对中文同样有效       |
| 自动调参        | 按上下文选择采样参数                  | DeepSeek 的 Anthropic 兼容接口只接受 `temperature` 与 `top_p`，`top_k` 等参数不会下发 |
| 输出整形        | 去退让语气 / 直给 / 口语              | 只影响聊天显示与赛跑结果的复制，不改写本地保存的原文                                  |

- 触发词表是中英双语的（英文 60 余个、中文 90 余个），中文按子串匹配、英文按词边界匹配，见 `src/services/unrestricted/parseltongue.ts`；
- 输入框工具行新增「扰动」按钮，点开可以开关、切换技术、查看命中数量与实时改写预览；
- 实验台「越狱方法」页新增「先用扰动改写测试语句」，提交前会对自定义测试语句做同样的改写；
- 实验台新增「多路赛跑」页：选 5 套 L1B3RT4S 提示词组合并发调用（可混合 `deepseek-v4-pro` / `deepseek-flash`），逐条流式展示，按 100 分制综合分（篇幅 / 结构 / 反拒绝 / 直接性 / 相关性）标出胜出者，并能「用此组合开新会话」——把该组合的系统提示词设为自定义提示词、问题填进输入框；
- 引擎代码集中在 `src/services/unrestricted/`，移植自 [G0DM0D3](https://github.com/elder-plinius/G0DM0D3)，保留 AGPL-3.0 文件头与许可证副本（`COPYING-AGPL-3.0`）。

### 3.11 思考强度、上下文占用、会话统计与费用估算

- **思考强度**：输入框原来的「深度思考」开关换成 0–4 档滑轨（关闭 / 轻量 / 标准 / 深度 / 极致）。档位写进请求：`thinking: { type: "enabled", budget_tokens }` 与 `reasoning_effort`（low / medium / high / max）；服务端返回 400 且报错里含 reasoning / thinking / budget / effort 时，自动去掉强度参数、退回 `thinking: { type: "enabled" }` 重试一次，并提示已降级。
- **流式输出**：设置 → 模型新增开关，默认开启；关闭后不渲染中间态，等完整回复生成完再一次性显示。防撤回仍作用于最终内容：拒绝回复在「防撤回」开启时保留，关闭时丢弃。
- **上下文占用**：输入框右下角的圆环按模型窗口（1M）折算本轮请求的上下文（`input + cache_read + cache_creation`），60% 以上变琥珀色、85% 以上变红色；悬停可看具体数值、压缩阈值（窗口 80%，预留 64k 余量与输出空间）以及压缩后的等效占用与节省量。
- **会话统计**（输入框右侧「统计」按钮）：会话回合、步骤（回复 + 工具调用）、输出速度、首 token 平均、模型用时、缓存命中率，以及未缓存输入 / 缓存读取 / 缓存写入 / 输出四个 token 数；生成中还会显示本次生成的实时数据。
- **自动越狱**（输入框工具行开关）：开启后 `system` 换成 GODMODE + 深度指令，强制输入扰动（未单独选技术时用全角）、强制自动调参、跳过安全审核；被安全拒绝（`stop_reason: refusal` 或正文命中拒绝话术）且没有保留正文时，按 L1B3RT4S 组合依次自动重试两次，全部失败会提示停止（每次重试都是一次真实请求，会产生额外费用）。
- **回复评分**：每条回复可点赞 / 点踩，评分连同该轮的上下文类型与采样参数写入 AutoTune 的 EMA 画像，后续自动调参会参考你的反馈（数据只在本机）。
- **会话级提示词**：赛跑「用此组合开新会话」只作用于新会话，会话顶部有提示条可一键恢复默认，不再覆盖设置里的提示词预设；该提示词随会话保存在本机（IndexedDB），历史导出包里不含它。
- **费用估算**：按官方定价页（元 / 百万 tokens）估算，`deepseek-flash` 与 `deepseek-v4-pro` 分别计价（每条回复按自己的模型算，未知模型按 Flash 兜底），并区分高峰 / 空闲：北京时间工作日 9:00–12:00、14:00–18:00 为高峰（空闲价是高峰价的一半），可按「今天算节假日」整体切到空闲价；另外计入联网搜索 / 网页抓取（5 元 / 1000 次）、文档解析（1.5 元 / 1000 页，按文件大小估算页数）、语音合成（3 元 / 万字符，可关掉限时 5 折）与语音识别（0.78 元 / 小时）。

### 3.17 长期记忆与每日用量

**长期记忆**（设置 → 记忆）：

- 手动添加 / 编辑 / 启停 / 删除 / 清空，启用的条目会注入每次请求的 `system`；
- 打开「自动提炼」后，每轮结束会额外调用一次 Flash，把稳定事实、身份、长期偏好写成 JSON 操作并更新列表（会产生少量费用，默认关闭）；
- 记忆只保存在本机，历史导出包不包含；与网状记忆库联动，启用的条目会同步成 `saved` 节点。

**每日用量与提醒**（设置 → 通用）：

- 统计当天 `input + cache_read + cache_creation + output` 的 token 与按模型 / 峰谷价估算的费用；
- 可设置每日 Token 上限与费用上限，达到后当天只提醒一次（toast），不会阻止请求；
- 统计弹窗的会话指标新增「今日 Token / 今日费用」，可随时重置今日计数。

### 3.18 网状记忆库（移植自 Operit）

设置 → 记忆 → **网状记忆库**：

- 节点包含标题、正文、标签、重要度、可信度；新增节点时按本地哈希向量的余弦相似度自动连边（最多 3 条，权重为相似度）；
- 检索同时计算关键词、标签、向量与关联边扩散分数，四项权重可分别调整；相关度阈值与每次注入条数可调；
- 向量维度可选 64 / 128 / 256 / 384 / 768，默认 256；向量在浏览器本地生成，不调用外部 embedding 服务；
- 「搜索调试」展示每个候选的关键词 / 标签 / 向量 / 关联分、总分与是否过阈值，并统计节点数、边数、命中数与边遍历次数；
- 请求时按当前问题检索 Top N，与长期记忆一起注入 `system`；没有命中时不会注入；
- 记忆库支持 JSON 导入导出，可选择「合并」（按内容去重）或「覆盖」；归档包含长期记忆与节点/边；
- 「关系图」把节点与带权重的边画出来，点击节点查看正文与标签；手机端保持可读尺寸并横向滚动；
- 直接展示当前向量维度、节点数、平均度与 Float32 预计占用；搜索调试额外显示维度、查询词数量与最高分；
- 聊天统计与输入框上下文圆环会显示记忆库节点/边/维度/上次注入条数；恢复默认设置会重置检索参数与每日提醒，但保留已保存的记忆数据；
- 手机端权重改为单列、搜索调试表格横向滚动，节点与标签自动换行。

### 3.20 搜索投毒

设置 → 搜索投毒。这个分组把客户端能控制的搜索输入全部开放出来：

| 能力           | 行为                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 当前时间       | 用 `datetime-local` 指定注入给模型的日期与星期；留空使用真实时间                           |
| 知识截止       | 声明模型数据库 / 训练数据截止日期；留空不声明                                              |
| 接管联网搜索   | 有自定义结果时不声明 `deepseek_web_search`，模型只看到过滤后的本地结果；关闭则保留真实搜索 |
| 结果替换       | 关键字或正则，按 URL / 标题 / 摘要 / 全部替换；正则支持 `$1` 捕获组                        |
| 黑名单         | 命中任意字段的结果从界面、导出和模型上下文中移除；自动接管搜索                             |
| 强制自定义结果 | 无论真实搜索是否命中，都把自定义结果注入模型并显示为搜索结果                               |
| 白名单         | 只保留命中白名单的自定义结果；服务端结果全部不返回                                         |

- 规则引擎在 [`src/services/searchPoison.ts`](../../src/services/searchPoison.ts)：替换、黑名单、白名单都先于注入执行；最多 50 条规则、20 条自定义结果；
- 自定义结果会进入 `system`，长内容会增加输入 token；单条摘要上限 4000 字符；
- 接管模式：请求体 `tools` 只保留 `deepseek_read_url`，`system` 末尾追加 `[LOCAL SEARCH LAYER]` 分块，自定义结果同时补一个「投毒搜索」步骤，显示在回复时间线里，底部网页汇总可打开；
- 非接管模式：仍使用服务端搜索；结果块进入客户端时替换 / 拉黑，正文引用角标同步替换 / 过滤，但服务端本轮已经消费过的结果无法撤回；
- 自定义时间写入 `latest_reminder` 的日期、星期与位置，知识截止和搜索结果写入 `system`；界面时间、计费、天气、定位不变；
- 与防撤回、流式输出兼容：只影响请求上下文和结果展示，拒绝内容保留逻辑不变；关闭流式时仍在结束后一次性显示投毒步骤；
- 所有配置存 `chat-demo:search-poison`，恢复默认设置会重置；接管搜索时真实联网搜索不会执行，需要真实搜索请关闭接管或清空黑名单 / 白名单。

### 3.21 附件投毒

设置 → 附件 → 附件投毒。默认关闭；启用后在上传前用浏览器本地处理改写附件，模型读取附件时会看到你填写的文本。

| 方式                 | 适用文件                            | 说明                                                       |
| -------------------- | ----------------------------------- | ---------------------------------------------------------- |
| 文本正文注入         | TXT / MD / CSV / 代码 / HTML / JSON | 在正文前或后插入带 `[ATTACHMENT NOTE]` 标记的文本          |
| DOCX 正文注入        | `.docx`                             | 解压后在 `word/document.xml` 的 body 末尾追加段落          |
| 图片文字覆盖         | PNG / JPG / WebP / GIF 等位图       | 在图片顶部或底部绘制文字面板，模型通过视觉 / OCR 读取      |
| 图片元数据（实验性） | JPEG / PNG                          | 写入 JPEG COM 或 PNG tEXt 元数据，部分解析器会读到         |
| 文件尾附加（实验性） | PDF / 未知二进制                    | 在文件末尾追加文本；ZIP 类 Office 文件自动跳过             |
| 文件名注入           | 所有格式                            | 把内容前 40 字写进上传文件名，模型能看到文件名时生效       |
| 伴随文本附件         | PDF / Office / 任意格式             | 额外生成一个 `.txt` 随消息发送，最可靠，但占用一个附件名额 |

- 方式可多选，按文件类型自动选择实际生效的处理；处理失败时回退为原文件，不阻断上传；
- 内容上限 4000 字符，统一带 `[ATTACHMENT NOTE]` 标记；文字、DOCX 与图片文字面板可放在正文前或后；
- 原始文件仍保存在 IndexedDB，上传的是处理后的副本；重新上传时可以按新配置重新投毒；
- 修改设置后，下一次发送会按当前配置重新上传输入框里有本地原件的附件；已发送的历史附件不会重写，没有本地原件的导入附件保持原样；
- 启用 / 关闭或切换伴随附件时，输入框里的原附件会立即重新上传；伴随文本附件在启用 / 关闭时自动同步，修改内容后请重新选择附件；
- 恢复默认设置会关闭并清空附件投毒配置，并移除草稿中自动生成的伴随文本附件；
- 图片文字覆盖会重新编码图片，GIF / 动图会变成静态图，GIF / BMP 等可能转成 PNG；PDF / Office 建议优先使用伴随文本附件。

### 3.22 自定义思维链

设置 → **思维链**。默认关闭；打开后把预先写好的推理步骤作为独立 system 分块注入每次请求，让模型按你定义的顺序推理，而不是只靠一句「请逐步思考」。

正文自带一份默认提示词（内置的 `thinking_prompt`）：首次使用、点「填入默认提示词」、恢复默认设置都会用它，仍可在设置页或输入栏卡片里自由改写。

| 深度思考       | 注入内容                  | 行为                                                                     | 稳定性   |
| -------------- | ------------------------- | ------------------------------------------------------------------------ | -------- |
| 关闭（0 档）   | `[自定义思维链]`          | 模型在内部按步骤作答；回复上方显示「已注入思维链」卡片，随后显示最终回答 | 常规能力 |
| 开启（1-4 档） | `[自定义思维链 · 实验性]` | 作为服务端思考的引导；服务端可能忽略、调整或重写这些步骤                 | 实验性   |

- 输入栏重新排版：第一排为模型 / 自动越狱 / 扰动，第二排为思维链 / 智能搜索 / 深度思考；手机端仍是一行横向滚动；
- 输入栏「思维链」按钮改为卡片入口，与设置页共用同一份配置：可直接开关、编辑、填入示例、清空，或点「打开设置」查看完整说明与 system 预览；
- **关闭深度思考时，回复上方会显示「已注入思维链」卡片**（默认展开、可折叠），内容是这一轮实际写入 system 的步骤，不再只显示最终回答；它不是服务端返回的 thinking，而是用户预设的推理步骤；
- 开启深度思考时不重复显示该卡片，服务端 thinking 照常展示；思维链仍作为实验性引导注入；
- 每条回复保存本轮注入快照：续写沿用原快照，重新生成读取当前设置，避免中途修改设置导致同一轮前后不一致；
- 思维链放在 Persona / 破限规则之后、长期记忆与搜索上下文之前；首轮请求同时带标题生成，也会注入，否则新会话第一条回复不会生效；
- 正文上限 4000 字符；只保存在本机 `chat-demo:custom-cot` 与 `chat-demo:custom-cot-enabled`，每轮都会增加输入 token；
- 只修改 `system`，不改消息结构：流式 / 非流式、续写、重新生成、标题生成、附件、搜索投毒与历史导入导出都保持兼容。

### 3.23 统计、图表与上下文管理

**位置：** 设置 → **统计**，以及输入栏的会话统计弹窗。

- **用量账本**（`usageLedger`）：每轮请求结束时按「日 / 模型」记账，记录未缓存输入、缓存读取、缓存写入、输出、预估费用、请求次数与联网搜索次数；账本在 localStorage 里保留最近 400 天，只存聚合数字、不含对话正文，和只管今天（用来触发额度提醒）的每日用量分开。
- **范围切换**：今天 / 7 天 / 30 天；中间没有请求的日期补 0，保证图表坐标连续。
- **KPI 区**：总 token、预估费用、缓存命中率、请求次数、有用量的天数、联网搜索次数。
- **每日趋势柱状图**：可切换指标——token（右柱为费用）、费用、请求数；每天一对柱子，悬停显示当天明细。
- **活跃热力图**：最近 8 周，每天一格，按窗口内最忙的一天分四档强度。
- **小时分布**：把所选范围内 24 小时的请求数画在一根轴上，能看出自己一般什么时候在聊；下方注明最忙的一小时。
- **输入构成环**：未命中缓存输入 / 命中缓存输入 / 缓存写入 / 输出，各带 token 与占比，一眼看出费用主要来自哪一段。
- **按模型拆分**：所选范围内每个模型的请求数、token 与费用；未知模型按 Flash 单价估算。
- **会话排行**：范围内按 token 排序的会话，带费用与请求数；点「打开」直接跳到该会话（会话已删除时按钮置灰）。
- **附加用量**：联网搜索、文档解析页数、语音合成字符与语音识别秒数——token 统计覆盖不到的计费项；本地模型只影响 token 费用，这些附加项照常计费。
- **上下文统计管理**：当前会话上下文对照模型窗口与压缩阈值，下面是记录中的会话表格，含上下文体量、窗口占比与最近请求时间；可清除单条、清空全部记录、导出 JSON / CSV、清空用量账本。
- **账本 v2**：每天记录里增加 24 小时直方图与会话维度拆分；旧版 v1 账本读取时按缺省值补齐，升级不需要迁移脚本；损坏的 JSON 当作空账本处理，不会带崩页面。
- **上下文分类**：把当前会话最近一轮请求拆成系统提示词 / 工具定义 / 用户消息 / 模型回复 / 模型思考 / 工具调用 / 工具结果 / 附件，各自给出估算 token 与占比；估算按字符权重，准确用量仍以 KPI 区服务端上报的数字为准。
- **计费口径**：按模型列出未命中 / 命中 / 输出的单价（元 / 百万 token），并摊开联网搜索、文档解析、语音合成与识别的单价，标注工作日高峰翻倍规则，账单对不上时可以直接对照。
- **服务端搜索免费开关**：按官方新政策（北京时间 2026-11-18 12:00 起），模型调用触发的服务端搜索、网页抓取不再计费，只按 Token 计费；开关默认开启。关闭后按旧规则（5 元 / 1000 次）估算，便于对旧账单。

**输入栏会话统计弹窗**新增本次会话输出趋势（迷你折线 + 最新 / 平均 / 最长）、用于横向对比的「最近 7 天用量」、输入构成环、附加用量卡（搜索 / 抓取 / 解析文件与页数 / 语音字符 / 语音秒数），以及带剩余窗口与压缩阈值的上下文压力表；底部可直接跳到设置 → 统计。

**API Key 脱敏**：越狱实验台不再渲染完整 Key，改成 `sk-****` 加末四位，并提供「在设置中修改」跳到设置 → 数据管理，和设置页自己保存 Key 的掩码展示保持一致。

> 这些工具的实际下发范围还受输入栏「聊天模式」控制：仅聊天模式一个都不发，网页 Agent 模式发浏览器 + 工作区，PTC / 创造模式再加上 NanoVM。详见 3.27。

### 3.24 浏览器 Agent 工具

**位置：** 设置 → **浏览器工具**。移植自 `DeepSeek-Agent` 的 browser / widget 工具，只保留浏览器能力；MCP 工具、子 Agent 与工作区（桌面端）工具按要求没有移植。

| 工具           | 做什么                                                                | 说明                             |
| -------------- | --------------------------------------------------------------------- | -------------------------------- |
| 时间日期       | 本地化日期、ISO 时间、星期与时区偏移，可指定 IANA 时区                | 只读，不联网                     |
| 网络定位       | 经纬度、精度与逆地理得到的城市名                                      | 浏览器会弹定位授权               |
| 天气查询       | Open-Meteo 当前天气 + 1–7 天预报，可传城市名或经纬度                  | 无需 API Key；都不传时尝试定位   |
| 发送通知       | 系统桌面通知                                                          | 首次使用请求权限                 |
| 读取剪贴板     | 返回剪贴板纯文本                                                      | 执行前需要确认                   |
| 写入剪贴板     | 把文本写进剪贴板                                                      | 会写入本机                       |
| 抓取网页       | 抓取页面正文并转纯文本，限制字符数                                    | 受目标站点 CORS 限制             |
| 生成文件       | 产出可预览、可下载的文件（Markdown / HTML / CSV / JSON / SVG / 代码） | 执行前需要确认；只存在本机       |
| 打开链接       | 在新标签页打开 URL                                                    | 可能被弹窗策略拦截               |
| 生成可视化组件 | 在沙箱 iframe 里渲染自包含的可交互 HTML                               | 沙箱没有同源权限，读不到聊天页面 |

- **每一项都能单独开关。** 主开关关闭时一个工具都不下发；关掉某一项后模型完全看不到它，若模型凭历史记忆调用，执行阶段会直接拒绝并说明原因，不会真的执行。
- **工具往返发生在同一条回复里**：模型给出 `tool_use`，页面本地执行，结果作为 `tool_result` 回传后继续生成（最多 4 轮）。每一轮都是一次真实请求，token 按轮计费。
- **工具卡片**展示工具名、参数摘要、状态与耗时，展开可看原始参数与结果；产物在卡片下方：文件给预览与下载，组件直接在沙箱 iframe 里渲染，可运行脚本但读不到聊天页面数据。
- **执行确认**：读取剪贴板与生成文件会先弹窗展示完整参数，可勾选「本次会话都允许」；拒绝会以错误结果回传给模型，回复不会卡住。
- **环境检测**：通知、定位、剪贴板在当前浏览器不可用时会标注并禁用对应开关，而不是等到调用时才失败。
- 全部在本机完成：工具结果与产物随回复保存在本地，历史导出包里不含这些字段。

### 3.25 虚拟工作区

**位置：** 设置 → **工作区**。完全活在浏览器存储里的文件库，不需要后端也不碰真实磁盘，让 Agent 有一个可以跨对话长期保存笔记、报告与生成文件的地方。

| 组成        | 行为                                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件        | 任意格式：文本可新建 / 在线编辑（改路径即重命名），图片、PDF、压缩包等二进制按原始字节保存；均可删除、预览、单文件下载                                                                  |
| 限制        | 按字节计算：OPFS 模式根据浏览器实际配额动态放大（最多用 80%，上限 64GB 总量 / 256MB 单文件），localStorage 模式受浏览器 5–10MB 限制、单文件软上限 4MB；设置页显示实时占用与当前生效上限 |
| 导入 / 导出 | 「导入文件」接受任意格式（可多选）；「导出 ZIP / 导入工作区」整包往返，二进制原样保留；旧版 JSON 备份仍可导入。归档导入可选合并（同名覆盖）或覆盖全部                                   |
| 路径        | 只允许相对路径，拒绝 `..`、绝对路径与盘符，避免出现奇怪的键名                                                                                                                           |
| 工作区工具  | `list_workspace`、`read_workspace_file`、`write_workspace_file`、`diff_workspace_file`、`delete_workspace_file`；写入与删除需要确认，diff 以文件进入工作区时的内容为基线                |
| 存储方式    | 浏览器本地存储（localStorage，默认）或 **OPFS 真文件系统**，可在设置里随时切换，切换时把现有文件整体复制到新后端                                                                        |
| 持久化      | 可点「申请持久化存储」调用 `navigator.storage.persist()`，并展示授权状态、已用空间与配额；降低浏览器在空间不足时清理数据的风险                                                          |
| 默认值      | **关闭**。Agent 主开关与工作区开关都从关闭开始，全新安装不会下发任何工具                                                                                                                |

- 关掉工作区后，即使 Agent 主开关打开，模型也看不到任何工作区工具；若模型凭历史调用，执行阶段会直接拒绝。
- 这里的内容不会上传。历史导出包不含工作区，清浏览器数据前请自行导出备份。

### 3.26 NanoVM Slim（浏览器里的 WASM shell）

**位置：** 侧栏底部 **NanoVM Slim**（在「实验台」「设置」上方）打开终端；控制台在 设置 → **NanoVM Slim**。

一个跑在页面里的轻量 POSIX 环境：WASM Shell Engine + busybox 风格命令集，不需要后端、不碰真实磁盘，文件都存在浏览器里。

| 组成       | 行为                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 引擎       | 首次执行命令（或点开终端且「首次使用时加载引擎」为开）时才动态加载引擎 chunk，首屏不下载；引擎按「内存分配」实例化 WASM 线性内存，管道缓冲走这块内存，超配额返回 `Cannot allocate memory`                                                                                                                                                                                                                                                                                                                                                                                                      |
| 终端       | 桌面端停靠在聊天右侧（默认 420px，可拖拽宽度；关掉「右侧常驻」改成浮层）；手机端是底部面板，键盘弹出时自动填满键盘上方，可拖拽高度、可全屏；支持多标签、↑↓ 翻历史、Ctrl+C 中断                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 切换输入法 | 手机端输入行的键盘按钮可以呼出系统输入法选择器（APK 里走原生 `InputMethodManager`），换键盘不用离开终端；纯浏览器没有这个能力，会提示用系统快捷键                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 重置       | 桌面头部与手机工具条都有红色「重置」：二次确认后清空虚拟机里的全部文件并重启引擎（设置里的控制台同样可以重置）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| busybox    | 130 个内置命令：文件与系统（`ls cat cp mv rm mkdir rmdir touch ln stat chmod du df ps free env export which` …）、文本（`grep sed awk sort uniq cut tr wc nl rev tac paste find xargs tee` …）、字节与数据（`sha512sum strings hexdump xxd od column fold expand unexpand numfmt cmp base32`、`jq` 子集、`zip unzip split shuf join comm`、`basename dirname realpath readlink mktemp nproc timeout`、开发工具 `patch bc expr tree fmt time uuid getopt tsort envsubst dotenv sponge`）、归档与校验（`tar gzip gunzip sha256sum md5sum base64 cksum diff`）、网络（`curl wget`，受 CORS 限制） |
| 联网       | `wget` / `curl` / `ping` 自动补 `https://`；**APK 走内置代理**（本地 127.0.0.1 反向代理，用 Android 的 `HttpURLConnection` 真发请求，不受 WebView 的 CORS 限制），普通浏览器直连只能访问允许跨域的站点；设置 → NanoVM Slim → **联网代理** 可以切直连或填自己的代理前缀（支持 `{url}` 占位）                                                                                                                                                                                                                                                                                                    |
| 虚拟网络   | 浏览器里没有 socket，所以 `vm serve <端口> <命令>` 用 **CGI 模型**注册服务：`curl http://127.0.0.1:<端口>/` 时把命令跑一次（环境变量给请求、stdin 给 body、stdout 按 CGI 格式回响应）；`serve <端口> [目录]` 起静态站、`vm serve --ws` 注册 WebSocket（`wscat` 单消息）；Node 的 `http` / `ws` 与 Python 的 `nanovm_serve`（Flask 等 WSGI 应用）都挂在这套网络上。没有常驻进程与长连接，大响应会整体缓冲                                                                                                                                                                                       |
| 按需工具链 | 运行时：Python 3（Pyodide，约 12MB）、Node.js 兼容运行时（无需下载）、Lua 5.4（wasmoon，约 0.4MB）、SQLite 3（sql.js，约 1.3MB）；构建工具：esbuild（约 12MB）、TypeScript（tsc，约 9MB）、Sass（约 5.8MB）、Terser（约 1.1MB）、Prettier（约 2MB）、GNU make（内置）；工具：Git（内置实现）                                                                                                                                                                                                                                                                                                   |
| 包管理     | `vm install python`、`vm uninstall python`、`vm list`、`vm info`、`vm mem`、`vm df`；安装进度直接打在终端里，Agent 也能调用                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 控制台     | 开关（启用、允许模型调用、首次加载、桌面常驻）、内存与虚拟磁盘配额、命令超时、引擎状态、存储位置与用量、镜像导入导出（zip）、重置；工具链按「运行时 / 构建工具 / 命令行工具」分组，卡片显示体积、状态、版本与示例命令（可点击复制）                                                                                                                                                                                                                                                                                                                                                            |
| 存储       | 虚拟磁盘落在 OPFS（`chat-demo-nanovm`），不支持时回落 localStorage；导出的 zip 含 manifest 与完整文件树，可在另一台设备导入                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Agent 工具 | `nanovm_shell`（执行命令，需确认）、`nanovm_ls`（只读列文件）、`nanovm_install`（装运行时，需确认）；默认**关闭**，总开关或「允许模型调用 Shell」任一关闭时模型完全看不到这三个工具                                                                                                                                                                                                                                                                                                                                                                                                            |
| 默认值     | 启用 NanoVM Slim，**允许模型调用关闭**；内存 128MB、磁盘 64MB、命令超时 15 秒                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

- 终端里的命令不联网（例外：`vm install`、`curl` / `wget`，以及聊天本身的 API 请求）。
- 中文注释、UTF-8 文件名、多行输出、管道与重定向都支持；`&` 后台进程不保留（没有作业控制）。
- 第一次安装 Python 需要联网，之后从本机缓存加载；Node.js 与 Git 是内置实现，离线可用。

### 3.27 聊天模式（仅聊天 / 网页 Agent / PTC / 创造）

**位置：** 输入栏「思维链」左边的模式胶囊，样式与模型切换一致，点开是四项菜单。

模式只决定「这一轮把哪些客户端工具下发给模型」，是在设置开关之上再加的一道限制：设置里关掉的工具，模式允许也不会发。

| 模式           | 下发的工具                                                                | 客户端工具往返上限 | 特有行为                                                                                                         |
| -------------- | ------------------------------------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **仅聊天**     | 只有服务端工具（读链接 / 联网搜索），浏览器、工作区、虚拟机工具一个都不发 | 4                  | 长期记忆、搜索投毒、自定义思维链照常生效                                                                         |
| **网页 Agent** | 浏览器工具 + 虚拟工作区工具                                               | 8                  | 抓网页、通知、剪贴板、工作区读写                                                                                 |
| **PTC**        | 网页 Agent + NanoVM Slim / WebVM（shell / 文件 / 安装）                           | 16                 | 同一轮的多个工具调用**并发执行**，工具之间可以接力                                                               |
| **创造**       | 同 PTC                                                                    | 24                 | 允许模型 `vm install python`、把脚本写进 `/usr/bin` 并 `chmod +x` 当成新命令；虚拟机写操作与安装**不再逐次确认** |

- 模式随 system 一起下发一段能力说明，模型知道这轮能用什么，不会在仅聊天模式里反复尝试调工具。
- 模型凭历史记忆调用当前模式不允许的工具时，执行阶段会拦下并提示「当前聊天模式不允许使用工具」。
- 默认模式是**网页 Agent**，与开启 Agent 之后的原有行为一致；选择记在 `chat-demo:chat-mode`。
- 菜单里会提示「当前设置：浏览器工具主开关已关闭 / 工作区开关已关闭 / NanoVM 未允许」，避免选了模式却以为已经生效。

### 3.28 应用内更新检测与安卓存储语义

**位置：** 设置 → **关于** 的「检查更新」卡片；工作区的存储状态在 设置 → **工作区**。

| 能力     | 行为                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 检查更新 | 读取 `api.github.com` 上本仓库的最新 Release，和构建时注入的版本比较；有新版时给出下载按钮（优先 Release 里的 `.apk` 直链，没有就跳发布页），并显示发布说明（折叠、前 500 字） |
| 安卓跳转 | 运行在 APK 里时额外提示「下载 APK 覆盖安装」，点击走系统浏览器，不会在 WebView 内下载                                                                                          |
| 存储语义 | 安卓壳的页面由本地服务注入 `nanovm-app` meta：此时工作区直接视为「应用存储」（不会被站点数据清理策略回收），不再显示「申请持久化存储」                                         |
| 配额     | 安卓壳默认使用 OPFS，并按 90% 配额计算上限（单文件最多 2GB、20000 个文件）；首次启动会把 localStorage 里的旧文件迁到 OPFS；浏览器仍是 80% / 64GB / 256MB                       |

- 更新检测只发一次匿名 GET 到 GitHub 公共 API，不带 API Key、不触发限流以外的任何请求；失败时原样显示原因。
- 存储迁移是单向的：迁到 OPFS 后 localStorage 副本会被清空，切回「浏览器本地存储」才会重新写入。

### 3.29 WebVM（CheerpX）

**位置：** 侧栏「WebVM」，或终端面板顶部的「NanoVM Slim / WebVM」切换器；设置 → **虚拟机** 下方的 WebVM 卡片。

**它是什么：** 第二个终端跑的不是模拟 shell，而是 CheerpX 提供的 x86 虚拟化 Debian 10。CheerpX 把 x86 指令 JIT 成 WebAssembly，在浏览器里直接执行真实的 Linux 二进制；根文件系统是从 `disks.webvm.io` 流式读取的 ext2 镜像，改动写进 IndexedDB 覆盖层。镜像自带 bash、coreutils、gcc / g++、Python 3、Node.js、Ruby、Perl、Lua 5.3 / LuaJIT、make、git、vim、nano、curl、wget 等环境，打开就能编译 C/C++、跑 Python / Node 脚本。

| 能力         | 行为                                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行         | 首次打开从 Leaning CDN 加载 CheerpX 1.4.0（约 1MB），并流式读取约 2GB 的 Debian 镜像块；之后从 IndexedDB 覆盖层缓存启动，磁盘改动刷新页面后仍在         |
| 与 NanoVM    | 两个实例同时存在；切换只换视图，WASM 引擎、CheerpX 进程、终端滚动历史与文件都不销毁。桌面停靠和手机底部面板都支持                                    |
| 终端         | xterm.js + 真实 PTY：方向键、Tab、Ctrl+C / Ctrl+D、vim、top 等全屏程序、IME 中文输入都可用；底部工具条有 Esc / Tab / 方向键 / 键盘 / 导入 / 导出 / 环境检测 |
| 跨源隔离     | CheerpX 需要 SharedArrayBuffer，即 COOP/COEP。静态站点第一次启用时注册 `coi-sw.js` 并刷新一次；Android WebView 不支持跨源隔离，APK 内会提示改用手机 Chrome / 桌面浏览器 |
| 镜像         | 默认 Debian 10（2026-06 镜像），可切到 2023 镜像或填自定义 `wss://` / `https://` / 同源 ext2 地址；不同镜像使用独立的覆盖层                               |
| 导入         | 文件写进只读 DataDevice 的 `/data`，再在 VM 里 `cp` 到 `/home/user/imports`；一次最多 50 个文件、20MB                                                    |
| 导出         | 在 VM 里 `tar czf - -C /home/user . \| base64 -w0`，浏览器捕获并下载 `webvm-home.tar.gz`；上限 32MB                                                     |
| 模型调用     | 新增 `webvm_shell` / `webvm_ls` / `webvm_status` 三个工具；与 NanoVM 工具同一分组（PTC / 创造模式才下发），执行前确认，创造模式自动放行               |
| 检测         | 设置卡片里的「检测环境」会在 VM 里跑 `uname`、`/etc/debian_version` 与 24 个命令的 `command -v`，直接显示哪些语言 / 工具存在                            |
| 提权         | WebVM 默认以 user 运行；预置 sudo 函数（调用镜像的 setuid `su`，root 密码 `password`），`sudo -i` 或工具栏 Root 按钮进入 root；root 只在浏览器虚拟机沙箱内有效 |

- **为什么不能用 `cx.run()` 跑模型命令：** CheerpX 的 Linux 只有一个控制台。再起一个进程虽然能输出，但它退出后交互式 bash 的 stdin 不再回来，用户之后敲什么都没反应。所以 WebVM 的模型命令与导入导出都写到 `/data/agent_xxx.sh`，在**现有 shell** 里用 `timeout N bash /data/...` 执行，并用开始 / 结束标记框住输出。
- **并发与超时：** 模型命令串行执行，单次工具上限 5 分钟（首次启动要等镜像块）；普通命令 30–60 秒。超时只保证工具返回，已启动的命令仍可能继续跑完。
- **网络：** 默认不配置网络（CheerpX 的联网需要 Tailscale 登录），因此 WebVM 里没有 `apt install`；镜像已经预装常用环境。需要联网时请在自定义镜像里自带工具，或改用 NanoVM 的虚拟网络。
- **许可：** CheerpX 是 Leaning Technologies 的专有软件，个人与开源项目可免费使用；商业使用需要商业许可。设置卡片与文档保留署名与链接。

### 3.30 关键词拒答（参考 DeepChat）

**位置：** 设置 → **模型** → 「关键词拒答」分组。

| 配置           | 行为                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 启用关键词拒答 | 仅检查**用户输入**；命中下方任意关键词时，直接在本地生成一条已完成的拒答回复，不发起 API 请求                                        |
| 拒答关键词     | 换行或中英文逗号分隔，子串匹配；空列表视为不启用                                                                                     |
| 区分大小写     | 关闭时英文关键词按小写比较；中文不受影响                                                                                             |
| 自定义拒答话术 | 命中时显示这段文字；留空使用默认 `replyRefused`（“你好，这个问题我暂时无法回答……”）                                                |

- **本地回复长什么样：** `status: 'done'`、`stopReason: 'refusal'`，正文作为模板块写入会话；因此不会出现流式光标，也不会进入上下文或续写前缀。
- **无 API Key 也能拒答：** 输入栏在命中关键词时会跳过 `ensureApiKey()`，直接把本地拒答写进会话；其余消息仍要求配置 Key。
- **扰动兼容：** 同时检查原始输入与扰动后的 `content`，避免开启输入扰动后绕过关键词。
- **不是安全边界：** 只是本地子串匹配，不做语义判断；附件内容、模型输出、图片文字都不会被检查。需要真正的审核请用服务端或外部审核。
- 配置只写 localStorage：`chat-demo:refusal-enabled` / `chat-demo:refusal-keywords` / `chat-demo:refusal-case-sensitive` / `chat-demo:refusal-message`。

### 3.31 本地模型（移植自 web-llm-chat）

**位置：** 设置 → **本地模型**，以及输入栏模型卡片顶部的「本地模型」分组。

移植自 [`mlc-ai/web-llm-chat`](https://github.com/mlc-ai/web-llm-chat)，保留它的模型目录、WebLLM 推理、MLC-LLM API 客户端与推荐采样参数，按本项目的静态构建方式重写为独立服务与设置分组。

**浏览器模型（WebLLM）**

- 目录来自安装的 `@mlc-ai/web-llm` 的 `prebuiltAppConfig`：只保留当前版本支持的模型（不含 embedding 模型），家族 / 厂商 / 参数规模 / 量化 / 显存需求与官方推荐采样参数来自移植过来的 `DEFAULT_MODEL_BASES`；
- 推理跑在 Web Worker 里（`src/services/local/worker.ts`），主线程只收进度：下载权重、编译 wasm 与初始化 GPU 都在后台，下载进度显示在设置卡片；
- 「下载」即「加载」：权重与 tokenizer 写入浏览器的 Cache Storage（`webllm/model`、`webllm/config`、`webllm/wasm`），刷新页面后不需要重新下载；「使用」把模型写进 `chat-demo:model`，聊天栏立刻显示本地模型；
- 可删除模型缓存；切换缓存后端（Cache Storage / IndexedDB）会卸载当前模型，已下载权重留在原后端；
- 上下文窗口默认跟随模型推荐值（4K / 8K / …），也可手动指定 1K–128K；温度、Top P、最大输出 Token、存在 / 频率惩罚、Qwen3 思考模式都在设置里，切换模型时先套用官方推荐值；
- 打开页面自动加载：开启后刷新即把上次的浏览器模型放进显存，失败时静默，原因在设置卡片里；
- 「恢复默认设置」会一并重置本地模型偏好（缓存后端、上下文窗口、采样参数、MLC 地址、自动加载）并卸载当前显存模型，已下载的权重不删除，仍可在目录里重新「使用」。

**MLC-LLM API**

- 填写自建 `mlc_llm serve` 服务的地址（默认 `http://127.0.0.1:8000`），「连接」后读取 `GET /v1/models`，选中即走 `POST /v1/chat/completions` 的 SSE 流；
- 与浏览器模型共用同一套消息管线：生成过程被包装成和云端一致的 `MessageStreamEvent`，所以流式渲染、停止、统计、Markdown 都与云端一致；
- 浏览器不需要 WebGPU，适合手机与 APK；附件同样只取文本。

**模型包导入 / 导出**

- 导出为 `.mlcmodel`：容器是「文件字节 + footer JSON + footer 长度」，footer 记录每个文件的 URL、所属缓存、偏移与大小；浏览器支持 File System Access 时直接流式写盘，否则退回 Blob 下载；
- 导入按 footer 用 `Blob.slice` 逐段写回 Cache Storage，几 GB 的权重不需要整包读进内存；导入完成后立即验证缓存并出现在聊天栏；
- 只支持 Cache Storage 后端；IndexedDB 后端下按钮置灰并提示。

**实测（2026-11，Intel Arc B390 / Chrome + WebGPU）**

- 目录 161 个聊天模型；下载并加载 `Qwen2.5-0.5B-Instruct-q4f16_1-MLC`（277 MB 权重 + 5.7 MB wasm）耗时 57 秒，状态从「正在准备模型」到「已加载到显存」；
- 提问「1+1 等于几？只回答数字」回复「2」约 2 秒；三句话自我介绍 64 个输出 token、约 3 秒（含 prefill），约 21 tok/s；
- 导出 `.mlcmodel` 277.4 MB、12 个文件（三个缓存作用域齐全），1 秒落盘；把该包导入一个全新的浏览器配置，模型立即显示「已下载」，断网状态下直接回复「9」，全程只有本地请求，0 次 `api.deepseek.com` 调用；
- 用量记账：Qwen2.5-0.5B 一轮 192 输入 / 64 输出 token，`billed 0`、`cost 0`。

**本地模型的增强（2.7.5）**

- **自动记忆**：设置 → 记忆新增「提炼模型」：跟随当前模型 / 固定 Flash API / 固定本地模型。默认跟随——云端对话走 Flash、本地对话走本地；云端对话也能用最近选中的本地模型提炼，本地对话不必强制调用 Flash。没有 API Key 也能用本地模型提炼；
- **深度思考合并**：本地模型设置里的「开启思考模式」并入输入栏「深度思考」，0 档关闭、1–4 档对 Qwen3 打开 thinking；WebLLM 传 `enable_thinking`，MLC-LLM API 在服务端支持时透传同名字段；
- **联网搜索（实验性）**：开启输入栏「智能搜索」且配置了 API Key 时，先借用 DeepSeek 服务端搜索做一次预检索，把要点与来源注入 system，再由本地模型作答；无 Key 时本轮跳过搜索并提示；
- **文本附件（实验性）**：本地模型不走 Files API，发送时由页面把 txt / md / csv / json / 代码等文本附件读成纯文本（单条 8K、总量 24K 字符上限）注入 system；图片与二进制附件跳过并提示；
- **仅聊天模式**：使用本地模型时 Agent / PTC / 创造模式置灰，只允许「仅聊天」，避免下发本地模型无法执行的工具。

**与云端模型的差异**

- 本地模型不发客户端工具（Agent / PTC / 创造不可选），搜索是生成前的服务端预检索，不是模型自己调用工具；
- 本地模型的回复没有服务端拒绝判定，`stop_reason` 由 finish_reason 映射（`length` → `max_tokens`，`content_filter` → `refusal`）；
- 用量来自引擎上报的 prompt / completion token，费用为 0，每日 token 额度只统计云端模型（新增 `billedTokens` 字段）。。

### 3.35 NanoVM 单文件导入（2.7.6）

**位置：** 设置 → 虚拟机 →「导入单个文件」，以及 Agent 工具 `nanovm_import`。

- **用户导入**：可从本机选择任意单个文件（zip / 图片 / 二进制），或从工作区列表里挑一个文件；目标目录默认 `/home/user`，也可填 `/tmp`；同名默认自动改名 `name-2.ext`，打开「同名覆盖」则替换；
- **直接写入**：不再把文件转 base64 塞进 shell 命令。页面读出 `File` / 工作区字节后调用 `vmFs.write()`，再 `persist()` 落盘；46MB 级文件也不需要几十轮命令；
- **自动扩容**：默认磁盘 64MB、单文件上限 32MB。导入前按文件大小与当前用量计算磁盘需求，自动把 `diskMB` 扩到能容纳该文件（最高 2048MB，单文件硬上限 256MB），并在提示里说明扩容后的值；
- **Agent 工具**：`nanovm_import` 支持 `workspace_path` 或 `content + encoding=text/base64`，`target` 可给目录或完整路径，`overwrite` 控制覆盖；与 shell / 安装工具一样需要确认（创造模式自动确认）；
- **可见性**：写入后 `vmFs.emit()` + 落盘，终端 `ls` / `wc -c` 立即可见；设置页的用量条同步刷新。

### 3.36 NanoVM 工具链：PyBot 超级专家系统（2.7.6）

**位置：** 设置 → 虚拟机 → 工具链 → PyBot，或终端里 `vm install pybot`；需要先安装 Python。

- **来源**：内置 [huggingface/pybot](https://github.com/huggingface/pybot) 快照（bot 源码提交 `24cbc04`，Apache-2.0），打包为 `public/pybot.zip`（约 13MB），安装时离线解压到虚拟机的 `/opt/pybot`，不依赖外网；
- **内容**：528 个 Python 文件、约 64 万行规则代码，无模型权重、无第三方依赖；
- **交互模式**：终端直接输入 `pybot` / `pybot -i`（或 `-v`）进入连续对话，提示符变成 `user>`；`/reset` 清空上下文（例如忘记名字）、`/help` 看帮助、`/exit` 回到 shell；PyBot 的会话内存在终端里保持，不再每轮重新加载；
- **一次性模式**：`pybot -p "问题"` 单次回答，`echo "问题" | pybot` 按行批量回答，`-v` 显示命中模块与耗时，`--version` 查看快照提交；
- **实现**：普通 `python3` 的同步上限是 16MB，PyBot 单独放宽到 64MB，启动时把 `/opt/pybot` 同步进 Pyodide 再执行 `pybot.py`；安装会按源码体积自动扩容虚拟磁盘（默认到约 83MB）；
- **实测**：首次安装 Python 约 23 秒（Pyodide 12MB），PyBot 解压约 3 秒；交互模式启动约 **6–8 秒**，之后每轮 2–5 秒（含模块调用），例如「my name is Sam」后问「what is my name?」回答「You're Sam.」，`/reset` 后答「I don't know it yet」；一次性与管道模式同样可用。

### 3.37 设置重组、记忆提示、头像裁剪与安卓输入栏（2.7.7）

**参考：** [DeepChat](https://github.com/xiaohuangbo/DeepChat) 的记忆更新提示、输入栏「+」面板、头像裁剪与侧边栏动效。

### 3.40 大文本附件与导入进度条（2.7.10）

**问题。** 纯文本附件（txt / md / csv / json / 代码）按文档上传后，服务端会把整份文件算进本轮输入 token。文件足够大（示例：188 KB 英文约 44k token、1.23 MB 约 290k token、4.87 MB 约 1.2M token）时，最后一份直接超过上下文：`This model's maximum context length is 1048576 tokens. ### 3.41 附件「token 过大」的真正原因（2.7.11）

**现象。** 2.7.10 的拆分把 326 KB 的 txt 拆成 4 片（96+96+96+34 KB）后仍然报错：

```text
user input too long, 69942 tokens exceeds max 32768 tokens (request_id: …)
```

**定位。** 用本地日志代理抓下应用真实发出的请求体，再逐项删字段重放：

| 请求字段 | 结果 |
| --- | --- |
| 原始请求（tools + safety_check + title） | 400 `user input too long, 60753 tokens exceeds max 32768 tokens` |
| 去掉 title | 仍然 400 |
| 去掉 safety_check | 仍然 400 |
| 去掉 tools | 仍然 400 |
| 去掉 title + safety_check（保留 tools） | 通过 |
| 三项全去掉 | 通过，`input_tokens` 6.4 万，正文正常读出 |
| 只加 tools / 只加 safety_check / 只加 title | 三者各自都会触发 32768 上限 |
| 只加 thinking / temperature / top_p / max_tokens | 不触发 |

也就是说：**只要请求里带 `tools`、`safety_check`、`title` 任一 DeepSeek 扩展字段，服务端就把「用户输入」（文字 + 附件解析结果）限制在 32768 token；不带这些字段的纯 Anthropic 兼容请求可以一直用到 1M 上下文。** 同一份 6 万 token 的正文改用纯文本消息发送也一样被拒，所以问题跟附件格式、分片数量都无关。RikkaHub 能读同样的 txt，是因为它把文档读成文本塞进 prompt，且请求里没有这些 DeepSeek 扩展字段。

**修复。** `streamReply` 在组装请求前用 `estimateUserInputTokens()` 粗估本轮用户输入（历史与当前提问的文字 + 附件按 4 字节 1 token），超过 32768 token 时：

- 不再下发 `tools`、`safety_check`、`title`，请求退化为纯 Anthropic 兼容路径，附件可以一直读到 1M 上下文；
- 从 `titleRequests` 里摘掉本轮控制器，避免这轮用量被当成标题请求不入账；首轮改用提问前 24 个字作为会话标题；
- 首次触发时 toast 说明「已自动去掉服务端工具、安全审核与标题请求」；
- 估算偏小、服务端仍回 `user input too long` 时，捕获 400 去掉这三项后自动重试一次，重试仍失败才展示原始错误。

小输入不受影响：同一份代码在输入低于阈值时照常下发安全审核、服务端工具与标题请求。

**涉及文件：** `src/services/chat/store.ts`、`src/services/api/types.ts`（`tools` 改为可选字段）、`src/i18n/{zh,en}.ts`。

### 3.42 非拉丁文字的记忆检索与标签图扩展（2.7.12）

**问题。** 2.7.10 之后，网状记忆库对俄语（西里尔）等非拉丁文字一直检索不到东西：在设置 → 记忆 → 搜索调试里输入与节点标题 / 正文 / 标签完全一致的俄语词，`查询词` 仍是 0，`最高分 0.00`，注入条数一直是 0。

**原因。** `tokenizeMemory()` 的正则只认两种文字：

```ts
const words = lower.match(/[a-z0-9_.-]{2,}/g)
const runs = lower.match(/[\u4e00-\u9fff]+/g)
```

拉丁字母走第一条、汉字走第二条，其余文字（西里尔、希腊、阿拉伯、天城文、假名…）两边都不匹配，整段被丢掉，查询侧与索引侧同时为 0，于是永远命中 0 个词。

**修复。** 分词改为 Unicode 规则：

- 汉字仍按单字 + 二元词组，保持中文召回；
- 其余文字用 `[\p{L}\p{N}]+(?:[_.'’-][\p{L}\p{N}]+)*/u` 按词保留；
- 先做 NFKC 归一化再转小写，全角字符、连字等输入法差异不会导致失配；
- 汉字区段在词切分前替换成空格，避免同一个字被两种规则重复计入；
- 英文 / 中文停用词照旧过滤。

修复后同一查询 `Москва столица`：`查询词 ['москва', 'столица']`，关键词命中 1 个节点，标签命中按标签计算，最高分不再是 0。中文检索行为不变。

**标签关联与图扩展（新开关）。** 设置 → 记忆 → 「标签关联与图扩展」，默认关闭：

- 开启后，新增 / 更新的记忆节点按共享标签自动连边，`type: 'tag'`，权重 `0.2 + 共享标签数 / 较大标签集 × 0.6`（最多 0.9），每个节点最多连 3 条，避免大标签簇把边数撑爆；
- 检索时除了原有的向量边扩散，还会按标签做动态扩展：种子节点把分数传给共享标签的节点，因此即使边是后来改标签、导入归档才出现的，也能被拉进来；
- 关闭时，`type: 'tag'` 的边在扩散阶段被忽略，检索行为与之前完全一致；
- 搜索调试多一个「标签扩展 N」计数，关系图里能看到标签自动关联产生的边。

**涉及文件：** `src/services/chat/memoryBank.ts`、`src/services/settings.ts`、`src/services/chat/savedMemory.ts`、`src/components/settings/MemorySettings.tsx`、`src/i18n/{zh,en}.ts`。

### 3.44 新会话首条消息不注入记忆（2.7.14）

**问题。** 用户在一个全新会话里发第一条消息，`Last injected` 有时显示有命中，但模型完全不知道记忆库里的内容，甚至去调用 `list_workspace` 翻工作区。

**原因。** 新会话的第一轮回复同时承担服务端标题生成：`streamReply` 在 `serverTitle && !session.title` 时把本轮 controller 放进 `titleRequests`。组装 system 时有一段：

```ts
const memoryContext = titleRequests.has(controller)
  ? ''
  : [savedMemoryEnabled ? formatSavedMemories() : '', memoryBankEnabled ? formatMemoryBankContext(...) : '']
      .filter(Boolean)
      .join('\n\n')
```

本意是「标题请求不需要记忆」，但标题与真正的回答是同一条请求：首轮被整段跳过，长期记忆和网状记忆库都没进 system。第二条消息标题已生成，才恢复正常——所以表现为「第一条永远没记忆」。

**修复。** 去掉 `titleRequests` 门控，记忆每轮都检索并注入：

- 首轮同样调用 `formatSavedMemories()` 与 `formatMemoryBankContext()`，检索结果进入 system；
- `useMemorySearchStats` 也会在首轮更新，`Last injected` 与真实注入一致；
- 注入块文案从「按需自然引用」改为「这些是用户此前确认过的资料：回答相关问题时直接引用其中的事实，不要声称不知道，也不要让用户重新提供」，减少模型明明拿到记忆却说没有的情况。

**验证。** 用真实密钥复现：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 新会话首轮请求的 `system` | 只有人格与模式说明 | 包含「以下是从用户网状记忆库检索到的相关记忆…」及命中节点 |
| 首轮提问「Какой мой любимый цвет?」（节点：бирюзовый） | 回答不知道 | 回答「бирюзовый (teal)」 |
| 命中统计 | 首轮不更新 | 首轮更新 |

### 3.47 自定义提示词注入工具（2.7.16）

设置 → 浏览器工具新增「提示词注入工具（自定义）」：把「回答正文」变成一次客户端工具调用的参数，收到回应后再还原为普通正文。工具本身不执行任何动作，只改变模型输出正文的通道。

**1. 配置（`src/services/agent/customInjection.ts`）。** 用户自己填写工具名、工具描述、参数名与参数说明，描述里要写明「把回答正文写进这个参数」：

```ts
type CustomInjectionConfig = {
  name: string            // 下发给模型的工具名，如 emit_answer
  description: string     // 写给模型看的说明
  paramName: string       // 正文参数，默认 content
  paramDescription: string
  forceToolChoice: boolean
  assistantRule: 'off' | 'generated' | 'all'
  userRule: 'off' | 'paired' | 'marked'
  marker: string          // userRule=marked 的前缀标记
}
```

- `sanitizeToolName` / `normalizeCustomInjection`：非法字符换成下划线、数字开头补 `tool_`、参数名不能与工具名相同、规则取值非法时回落默认；空名字允许存着（界面正在重填）但不视为可用，`customInjectionReady` 为 false 时不下发。
- `customInjectionDefinition`：生成 `ClientToolDefinition`，`required: [paramName]`、`additionalProperties: false`；描述为空时回落到默认文案。

**2. 请求组装（`store.ts` 的 `requestPlan`）。** 注入工具下发的名字 / 描述 / 参数都来自配置，因此静态注册表里的 `custom_injection` 只作设置页占位，请求时跳过、改用按配置生成的定义。强制模式追加 `tool_choice: { type: 'tool', name }`。

实测有三处字段与 `tool_choice` 冲突（服务端一律回 `Thinking mode does not support this tool_choice`）：

| 字段 | 处理 |
| --- | --- |
| 深度思考（`thinking.enabled`） | 本轮改成 `{ type: 'disabled' }`，并在会话内提示一次 |
| `safety_check` | 本轮不携带 |
| 服务端工具（`deepseek_read_url` / `deepseek_web_search`） | 本轮不下发 |
| `title: { enabled: true }` | 本轮不请求，标题回落到提问开头 24 字 |

**3. 正文还原（`reply.ts` 的 `applyCustomBody`）。** 流结束后如果工具槽里有注入工具调用，取出参数（`extractCustomBody` 优先配置的参数名，模型用了别的键时取第一个字符串），把它接回回答末尾：末尾是正文块就拼接，否则追加一个新的正文块；同时在回复上记 `customTool: { name, param }`。这条回复不再执行工具、不再带 `tool_result` 请求下一轮，`stopReason` 从 `tool_use` 改回 `end_turn`，`prefix` 恢复为 true，于是复制、编辑、统计与普通回复完全一致。

**4. 历史还原（`toRequestMessages`）。** 多轮上下文要与本轮的形状一致，否则模型会一边输出正文一边补一次工具调用：

- 规则：`convertAssistant`（only generated / all）决定哪条助手消息还原成 `tool_use`；`convertUser`（paired / marked）决定紧随其后的提问还原成它的 `tool_result`。
- 协议：`tool_use` 必须紧跟配对 `tool_result`，所以这轮的系统提醒从「提问之后」挪到「提问之前」；带附件的提问把 `tool_result` 排在文件块最前面；助手能还原的前提是下一条提问确实会进入请求（`userHasBody`），否则整轮放弃还原。
- 只在注入工具本轮真正下发时启用：工具被关掉、或大输入剥离扩展字段时不转换，避免请求里出现未声明的工具。
- 它不执行任何动作、只是输出通道，因此 `modeAllowsTool` 对它单独放行：仅聊天模式下也会下发这一个工具（其余浏览器工具照旧不下发）。
- `tool_use` 的 id 由回复 id 派生（`toolu_<id>`），同一分支多次请求保持稳定。

**5. 设置界面（`CustomToolSetting.tsx`）。** 可折叠卡片：头部显示工具名 / 参数名 / 强制标签 / 历史标签与开关，展开后是工具定义表单、强制开关、历史规则两个下拉与标记输入，底部「预览」同时给出下发给接口的工具定义 JSON 和转换后的历史形状。名字非法时卡片右上角显示警告并说明原因。卡片在定高滚动的设置面板里必须 `flex-shrink: 0`，否则会被压成一条线（首版实测 2px 高）。

### 3.49 latest_reminder 顺序修复（2.7.17）

修 2.7.16 引入的回归：带历史的请求会被服务端拒绝，报

```
messages.23: a `latest_reminder` message must be immediately followed by a `user` message
```

**根因。** 2.7.16 为了支持「自定义提示词注入工具」的历史还原，重写了 `toRequestMessages` 的轮次循环。为了让 `tool_use` 与 `tool_result` 之间不夹角色，代码把「插提醒」拆成了两条路径：

```ts
const reminderFirst = pendingToolUseId !== null || toolUse !== null
if (reminderFirst) appendReminder(reply.latestReminder)
messages.push(toUserParam(user))
if (toolUse) { ... } else {
  if (!reminderFirst) appendReminder(reply.latestReminder)   // ← 插到了提问之后
  messages.push(toAssistantParam(reply))
}
```

普通轮次（`reminderFirst === false`）于是生成 `user → latest_reminder → assistant`，而服务端要求 `latest_reminder` 后面必须紧跟 `user`。首轮没有历史，所以 2.7.16 的验收没暴露；第二轮起只要历史轮次的提醒快照与上一条不同就会触发，长会话里就表现为 `messages.N`。

**修复。** 提醒一律在提问之前插入，`reminderFirst` 这个分支直接删掉；同时补上两处服务端约束（都用真实接口验证过）：

| 形状 | 服务端 |
| --- | --- |
| `user → latest_reminder → assistant` | 400 `a latest_reminder message must be immediately followed by a user message` |
| `latest_reminder → latest_reminder → user` | 400（`latest_reminder must have at least …`） |
| `latest_reminder → user → assistant` | 200 |
| `assistant(tool_use) → latest_reminder → user(tool_result)` | 400 `tool_use ids were found without tool_result blocks immediately after` |
| `latest_reminder → user → assistant(tool_use) → user(tool_result)` | 200 |

由此还改了两处：

1. **压缩摘要与轮次提醒合并。** 压缩摘要本身以 `latest_reminder` 下发，后面若还有「提醒变化」的轮次，会出现连续两条提醒。`appendReminder` 现在检测到上一条已是提醒时，把新提醒拼进原有内容（`摘要\n\n提醒`），不再新增第二条。
2. **注入工具的历史还原让位。** 还原 `tool_use` 时，如果紧随其后的提问前需要插入新提醒（跨天、换定位导致快照变化），提醒就会被夹在 `tool_use` 与 `tool_result` 之间而被拒绝。`toRequestMessages` 先预演一遍提醒的插入位置（`reminderFlags`），遇到这种情况就放弃这一轮的还原，历史仍按纯文本回传；提醒没变化的轮次照常还原。

**验证。**

| 场景 | 结果 |
| --- | --- |
| 单测：2 / 3 轮历史、重复提醒、压缩摘要、压缩后仍有轮次、续写前缀、空提问跳过、无提醒 | 全部满足「提醒后紧跟 user、无相邻提醒、tool_use 后紧跟 tool_result」 |
| 单测：压缩摘要 + 首条轮次提醒合并成一条（内容含两者）、相邻提醒数为 0 | 通过 |
| 单测：注入工具还原路径——提醒不变时照常还原；提醒变化时该轮放弃还原 | 通过 |
| 真实接口三轮对话（deepseek-flash）：三次请求全部 200，角色序列 `latest_reminder,user,assistant,user,assistant,user`，三条回复 `done` | 通过 |
| 真实接口 + 注入工具：第二轮 `latest_reminder,user,assistant(tool_use),user(tool_result)`；改定位后再发一轮，最后一个提醒插在提问前、上一轮不再还原，请求仍 200 | 通过 |

### 3.52 去掉重复的内存设置、修复 Debian apt 的 403（2.7.19）

**1. 设置 → Unkernel Linux 不再有「内核内存」。** 上游页面自己的「设置 → 机器」里就有内存滑块（带按设备算出的自动值），而宿主传的 `?mem=` 会把内存钉死成一个值：在页面里改完重启，宿主的 URL 又把改动盖回去，两边打架。现在 `chat-demo:unkernel-config` 去掉 `memoryMiB`，`unkernelUrl()` 不再传 `mem`，内存只由页面设置（`kw.settings`）决定；宿主面板保留发行版、数据盘、CPU、设备、Worker、Wisp、超时，并在「资源」下面加了一句说明指向虚拟机自己的设置。Agent 的 `unkernel_*` 状态工具也不再报宿主配置里的内存，内存改由 guest 的 `free -m` 给出。

**2. Debian 里 `apt-get update` / `apt-get install` 报 403。** 根因不在 Debian，也不在 Wisp：新版页面默认把 `deb.debian.org`、`apt.ladybird.org`、`mirror.unkernel.dev` 的**纯 HTTP** 交给它自己的 CORS 镜像 `https://mirror.unkernel.dev`，由页面的 `fetch()` 代答（`web/src/config.ts` 的 `DEFAULT_ROUTES`）。该镜像带 Origin 白名单，只有白名单里的页面源能读：

| 页面源 | `GET https://mirror.unkernel.dev/deb/debian/dists/trixie/Release` |
| --- | --- |
| `https://unkernel.dev`（官方站） | 200 |
| `http://localhost:3080` | 200 |
| `http://127.0.0.1:3080`（本应用） | **403 `Origin not allowed`** |
| APK / 局域网地址（`http://127.0.0.1:18765` 等） | **403** |

镜像返回的 403 被页面的 fetch 层原样转给 guest，apt 于是报 `403 Forbidden`（索引请求在 CORS 层失败时显示 `503`）。官方站没有这个问题，是因为它的源就在白名单里。修法是给 iframe 加 `?routes=0`——上游为这种情况准备的开关：guest 的纯 HTTP 也走 Wisp，不再经过镜像；页面自己的脚本本来就会检查名字是否被路由到 `198.51.100.0/24`（`DEFAULT_ROUTES` 的标记网段），关掉路由后它们自动改用上游地址。

实测（本地最小 Wisp 中继 + 页面自带的 Debian 13 镜像）：

| 场景 | `apt-get update` | `apt-get install bzip2` |
| --- | --- | --- |
| `routes=0`（本版本） | 通过：`Get:1 http://deb.debian.org/debian trixie InRelease [140 kB]` … 10.2 MB / 16 s | 通过：`bzip2 1.0.8-6` 装上，`bzip2 --version` 正常 |
| 不传 `routes`（旧行为） | `503 Service Unavailable [IP: 198.51.100.1 80]` | `403 Forbidden [IP: 198.51.100.1 80]` |

顺带确认 Alpine 侧没有回归：`apk update`、`apk add curl` 正常，guest 里 `curl http://deb.debian.org/debian/dists/trixie/Release` 返回 200。代价写在 [10. 已知限制](10-known-limits.md) 第 87 条：apt 的索引与 `.deb` 现在经过公共 Wisp 代理（代理运营方能看到明文 HTTP 内容），依赖该镜像的应用会改用上游地址。

| 检查 | 结果 |
| --- | --- |
| 设置页「资源」 | 只剩发行版 / CPU / 数据盘 / 超时，滑块仅 CPU；说明指向虚拟机自己的设置 |

### 3.53 会话置顶与多选、DeepSeek 账号登录、恢复默认设置联动（2.7.20）

**1. 会话置顶与多选批量操作。** 会话行「…」菜单补上「置顶 / 取消置顶」与「多选」：置顶的会话单独进最前面的「置顶」分组（组内仍按最近更新排序，行尾有小图钉），其余按今天 / 昨天 / 7 天内 / 30 天内 / 按月分组，与官方客户端的列表一致。多选进入后列表头部变成「已选择 N 个对话」并带「全选 / 取消全选」与关闭按钮，新建对话与底部导航栏让位给「置顶 / 删除」操作条；删除走确认弹窗并显示数量。置顶标记存在会话摘要里（`sessionSummaries.pinned`），刷新页面与重开浏览器后仍在；导出用的是 DeepSeek 历史会话格式，不写置顶标记，导入后需要重新置顶；多选状态放在 `components/sider/sessionSelection.ts`，桌面侧边栏与移动端抽屉共用同一份，会话被删或导入替换后自动清理失效的选中项。

**2. 设置 → 数据管理新增「从 DeepSeek 账号登录」。** 用账号的 API Key 登录：只向 `api.deepseek.com/user/balance` 校验一次，成功即建立登录态（Key 尾号、余额快照、登录时间存在 `chat-demo:account-session`，不保存 Key 副本），账号卡显示头像、昵称、Key 尾号、余额与登录时间，并提供「刷新余额 / 同步账号昵称 / 编辑我的资料 / 退出登录」。与「通用设置 → 我的资料」联动：资料卡新增账号行，未登录时给登录入口，已登录时显示 Key 尾号并能一键把 `DeepSeek · 尾号` 写进昵称，资料与账号卡共用同一套昵称和头像；「账户与用量」读同一个 Key。

> 平台账号的网页授权（OAuth）走 `/auth-api/v0/dsh/auth_init` → 浏览器授权页 → `auth_exchange`，需要宿主服务接收回调，且这些接口不带 CORS 头，静态页面拿不到 token（deepseek-harness 也是放在 Node 宿主里做的）。因此这里用 API Key 登录，能拿到账号可用状态与余额，拿不到平台头像与昵称——写在 [10. 已知限制](10-known-limits.md) 第 88 条。

**3. 「恢复默认设置」联动。** 之前只重置设置项、提示词预设与本地模型偏好，NanoVM / WebVM / Unkernel 的启动参数和账号登录态会留在原样。现在统一走 `services/resetAll.ts` 的 `resetAllSettings()`：设置项、提示词预设、本地模型偏好（并卸载显存里的模型）、三个虚拟机的参数、账号登录态一起回默认；API Key、全部对话与附件、工作区文件、记忆库与统计数据保留（Unkernel 数据盘的大小与内容也不动）。确认弹窗改成「会重置 / 会保留」两段说明，点之前就知道会发生什么。
